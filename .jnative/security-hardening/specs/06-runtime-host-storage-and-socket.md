# 06: Runtime Host 落盘与 socket 加固

要先完成:无 · 状态:⬜

## 交付什么

会话数据库的读不再阻塞写，长时间读取期间发生的写入不会因为等锁超时而向用户报冲突。Runtime Host 的本地 socket 只有当前用户能连接，同机其他用户碰不到它承载的高权限接口。

## 范围

做:

- 给 SQLite 开 WAL。目前只设了外键和 5 秒等锁超时，走的是默认的 rollback journal，读会阻塞写。
- 给 Unix socket 显式设权限 0600，或者把它放进一个 0700 的目录。目前只有锁文件设了 0600，socket 本身没有设置，实际权限受 umask 影响。Windows 走 named pipe，需要确认对应的处理方式，或者明确记为不适用。
- 补测试。至少覆盖 WAL 已生效；socket 权限如果难以在测试里断言，写进「决策记录」说明为什么。

不做:

- 给本地 RPC 加身份认证。socket 承载的接口目前完全依赖文件系统权限，加认证是更大的设计问题，本项只把文件系统这层做对。
- 多连接争用的完整测试。评审指出目前没有这类测试，但正常路径有 Runtime Host 独占锁保护，补齐它的收益不足以放进本轮。写进「遗留问题」。

## 长期保存的数据与维护方

`~/.jai/data.sqlite`，owner 是 Runtime Host（`app/server`）。WAL 会让同目录多出 `-wal` 和 `-shm` 两个文件。schema 不变，事实归属不变，已有数据可以直接继续用。

要确认一件事：应用退出时 WAL 能否正常 checkpoint 回主库。如果异常退出留下未合并的 `-wal`，下次打开应当自动恢复，这是 SQLite 的既定行为，但要在测试里验证一次而不是假定。

## 必须遵守的项目规则

> - Durable journal 只有 SQLite：CLI 与 Desktop 共用 `$JAI_HOME/data.sqlite`（默认 `~/.jai/data.sqlite`）。不得新增 JSONL、双写、重建索引、fallback 或第二种 durable adapter。

WAL 是同一个数据库的日志模式，不是第二个 durable adapter。

> 2. 选能满足当前需求的最简单实现。不要预防性抽象，不要多此一举的配置层。

pragma 直接写在打开数据库的地方，不做成可配置项。

> - `main.ts`、`runtime.ts`、composition root 只负责装配与生命周期。

socket 权限设置属于生命周期的一部分，放在创建 socket 的地方。

## 风险

- WAL 会改变异常退出后的恢复路径。要验证强制杀进程后重新打开数据库，会话数据完整。
