# ACP v2 与 Jai 内部协议的适配判断

调研日期：2026-08-25  
ACP 规范取样：`agentclientprotocol/agent-client-protocol` 提交 [`5acaa3acda11e29d523193bfb3401c8497f5a90e`](https://github.com/agentclientprotocol/agent-client-protocol/tree/5acaa3acda11e29d523193bfb3401c8497f5a90e)  
Rust SDK 取样：`agentclientprotocol/rust-sdk` 提交 [`754d5aa1ce2cfa54ba2c2a6d3edc7e7b6bce28eb`](https://github.com/agentclientprotocol/rust-sdk/tree/754d5aa1ce2cfa54ba2c2a6d3edc7e7b6bce28eb)  
范围：只读官方 ACP v2 规范、迁移说明和 Rust SDK；不改生产代码。

## 结论

**ACP v2 适合作为 Agent 与外部 Client 之间的互操作/边界协议，不适合作为 Jai app/server 内部的 canonical 主协议，也不能替代 SQLite durable journal 或 operation log。**

ACP 规定了角色、JSON-RPC 生命周期、session 管理、能力协商、prompt 的异步状态与面向 UI 的更新；Pi/Maka 讨论的则是“哪些持久事实已经发生、崩溃后怎样归约、工具副作用是否允许重放”。两者处在不同层次：

```text
canonical SQLite journal + operation facts
        ↓
Jai runtime / host contract
        ↓
ACP v2 adapter（可选的跨进程、第三方 Client 边界）
        ↓
Desktop / IDE / 其他 ACP Client
```

ACP 的 `session/update` 应被视为安全的 client-facing projection；不能反向成为 journal 的事实源，也不能把内部异常、`cause` 或未筛选的 SDK 对象塞进 `_meta`。

## ACP v2 定义了什么

### 角色边界

ACP 将 **Agent** 定义为使用生成式 AI、能自主修改代码的程序；**Client** 通常是 IDE、编辑器或 TUI，负责用户交互、工作环境以及资源访问控制。Agent 向 Client 发送 `session/update`，展示消息、思考、计划、tool call、terminal display 和 usage；Client 向 Agent 发送 `session/prompt`、`session/cancel`，而 Agent 可调用 `session/request_permission` 请求 Client 展示权限提示并返回用户选择。[`overview.mdx`](https://github.com/agentclientprotocol/agent-client-protocol/blob/5acaa3acda11e29d523193bfb3401c8497f5a90e/docs/protocol/v2/overview.mdx#L6-L17) [`overview.mdx` 角色与 Client](https://github.com/agentclientprotocol/agent-client-protocol/blob/5acaa3acda11e29d523193bfb3401c8497f5a90e/docs/protocol/v2/overview.mdx#L48-L50)

这与 Jai 的产品拓扑可以自然映射，但不能照搬 ownership：在我们的系统里，Runtime Host/服务器仍应拥有 workspace、权限判定和 durable facts；renderer/Desktop 只能消费投影并呈现用户交互。

### Transport

协议格式是 JSON-RPC 2.0。v2 当前规范定义了：

- **stdio**：Client 启动 Agent subprocess，双方通过 stdin/stdout 交换换行分隔的 JSON-RPC；这是当前最完整、最明确的标准 transport。
- **Streamable HTTP**：规范标为进行中的 draft proposal。
- **custom transport**：允许自定义，但必须保留 JSON-RPC 格式和 ACP lifecycle 语义。

批处理消息可以并发、乱序处理，响应按 request id 匹配；`initialize`、`session/new`、`session/resume`、`session/prompt` 等生命周期调用不应批处理。[`transports.mdx`](https://github.com/agentclientprotocol/agent-client-protocol/blob/5acaa3acda11e29d523193bfb3401c8497f5a90e/docs/protocol/v2/transports.mdx#L6-L15) [`transports.mdx` batch 规则](https://github.com/agentclientprotocol/agent-client-protocol/blob/5acaa3acda11e29d523193bfb3401c8497f5a90e/docs/protocol/v2/transports.mdx#L45-L80)

Rust SDK 另外提供进程内 `Channel::duplex()`、通用 byte stream、TCP/Unix socket 等 transport seam；HTTP/SSE 与 WebSocket adapter 位于单独 crate，且 v2 仍需 `unstable_protocol_v2` feature。[`protocol-v2.md`](https://github.com/agentclientprotocol/rust-sdk/blob/754d5aa1ce2cfa54ba2c2a6d3edc7e7b6bce28eb/md/protocol-v2.md#L1-L30) [`transport-architecture.md`](https://github.com/agentclientprotocol/rust-sdk/blob/754d5aa1ce2cfa54ba2c2a6d3edc7e7b6bce28eb/md/transport-architecture.md#L259-L305) [`agent-client-protocol` README](https://github.com/agentclientprotocol/rust-sdk/blob/754d5aa1ce2cfa54ba2c2a6d3edc7e7b6bce28eb/src/agent-client-protocol/README.md#L43-L72)

### 初始化与 capability negotiation

建立 session 前 Client 必须调用 `initialize`，发送支持的主版本、capabilities 和必需的 `info`；Agent 返回协商后的版本、自身 capabilities、`info`，以及可选的认证方法。主版本是整数，破坏性变化递增；若 Agent 不支持 Client 请求的版本，返回其支持的最新版本，Client 无法兼容时应断开。[`initialization.mdx`](https://github.com/agentclientprotocol/agent-client-protocol/blob/5acaa3acda11e29d523193bfb3401c8497f5a90e/docs/protocol/v2/initialization.mdx#L6-L96)

capability 的语义是：字段省略表示不支持，空对象 `{}` 表示支持；能力应可组合，并可通过 `_meta` 添加自定义能力。基础 `session: {}` 覆盖 `session/new`、`session/list`、`session/resume`、`session/close`、`session/prompt`、`session/cancel` 和 `session/update`；图片/音频/embedded context、MCP stdio/http、session delete、additional directories 等是可选能力。[`initialization.mdx` capabilities](https://github.com/agentclientprotocol/agent-client-protocol/blob/5acaa3acda11e29d523193bfb3401c8497f5a90e/docs/protocol/v2/initialization.mdx#L98-L111) [`initialization.mdx` session capabilities](https://github.com/agentclientprotocol/agent-client-protocol/blob/5acaa3acda11e29d523193bfb3401c8497f5a90e/docs/protocol/v2/initialization.mdx#L145-L199)

需要保留成熟度判断：迁移文档称 `schema/v2/schema.json` 是稳定 baseline，但完整 v2 surface 仍标为 draft；Rust SDK 通过 feature flag 和显式 `Client.v2()` / `Agent.v2()` 暴露。因此不能把当前 v2 当成不需要版本隔离的内部唯一协议。[`migration.mdx`](https://github.com/agentclientprotocol/agent-client-protocol/blob/5acaa3acda11e29d523193bfb3401c8497f5a90e/docs/protocol/v2/migration.mdx#L18-L30)

### Session 生命周期

典型序列是：

```text
initialize
  → auth/login（若 Agent 宣布）
  → session/new 或 session/resume
  → session/prompt
  → session/update notifications
  → session/cancel（需要时）
  → state_update: idle + stopReason
```

`session/new` 创建 session 并返回 `sessionId`；`session/resume` 恢复已有 session，可用 `replayFrom: { type: "start" }` 请求历史重放；`session/list` 发现 session；`session/close` 取消进行中的工作并释放活跃资源。`session/delete` 是可选能力，规范只要求它从未来的 list 结果中移除该 session。`cwd` 和 `additionalDirectories` 必须是绝对路径。[`session-setup.mdx`](https://github.com/agentclientprotocol/agent-client-protocol/blob/5acaa3acda11e29d523193bfb3401c8497f5a90e/docs/protocol/v2/session-setup.mdx#L6-L38) [`session-setup.mdx` create/resume/close](https://github.com/agentclientprotocol/agent-client-protocol/blob/5acaa3acda11e29d523193bfb3401c8497f5a90e/docs/protocol/v2/session-setup.mdx#L42-L147) [`session-setup.mdx` close](https://github.com/agentclientprotocol/agent-client-protocol/blob/5acaa3acda11e29d523193bfb3401c8497f5a90e/docs/protocol/v2/session-setup.mdx#L219-L254)

ACP session 更接近“对话/上下文/连接的生命周期抽象”，不是 Pi/Maka 意义上的 durable operation journal。尤其不能仅凭 `session/resume` 推断 Agent 能从工具副作用的崩溃边界继续运行。

### Prompt 与 updates

v2 的关键变化是：`session/prompt` 在 prompt 被接受后立即返回空对象 `{}`，不再表示这一轮已完成。Agent 必须通过 `session/update` 发送用户消息已插入历史、`state_update: running`，之后发送模型消息、计划、思考和 tool call；完成时发送 `state_update: idle` 与 `stopReason`。需要用户决定权限时进入 `requires_action`；取消最终回到 idle/cancelled。[`prompt-lifecycle.mdx`](https://github.com/agentclientprotocol/agent-client-protocol/blob/5acaa3acda11e29d523193bfb3401c8497f5a90e/docs/protocol/v2/prompt-lifecycle.mdx#L6-L10) [`prompt-lifecycle.mdx` accepted/running/completion](https://github.com/agentclientprotocol/agent-client-protocol/blob/5acaa3acda11e29d523193bfb3401c8497f5a90e/docs/protocol/v2/prompt-lifecycle.mdx#L107-L157)

消息、thought 和 tool call 使用 opaque id/upsert：字段省略表示不变，`null` 表示清除，具体值表示替换，chunk 追加；replay 保留 id 与顺序。[`prompt-lifecycle.mdx` upsert](https://github.com/agentclientprotocol/agent-client-protocol/blob/5acaa3acda11e29d523193bfb3401c8497f5a90e/docs/protocol/v2/prompt-lifecycle.mdx#L228-L242) [`tool-calls.mdx` tool upsert](https://github.com/agentclientprotocol/agent-client-protocol/blob/5acaa3acda11e29d523193bfb3401c8497f5a90e/docs/protocol/v2/tool-calls.mdx#L83-L92)

这套 upsert 很适合 renderer/UI 的实时物化视图，但它不是 append-only domain fact：一个客户端可以根据 update 合并出“当前显示内容”，却不能由此判断某个 effect 是否已经持久化，或恢复时是否允许重放。

### Tool 与 permission

工具由 Agent 执行；Client 通过 `session/request_permission` 提供权限 UI/决策。工具状态包括 `pending`、`in_progress`、`completed`、`failed`、`cancelled`，更新主要用于展示和进度。[`tool-calls.mdx`](https://github.com/agentclientprotocol/agent-client-protocol/blob/5acaa3acda11e29d523193bfb3401c8497f5a90e/docs/protocol/v2/tool-calls.mdx#L6-L14) [`tool-calls.mdx` permission](https://github.com/agentclientprotocol/agent-client-protocol/blob/5acaa3acda11e29d523193bfb3401c8497f5a90e/docs/protocol/v2/tool-calls.mdx#L167-L224) [`tool-calls.mdx` status](https://github.com/agentclientprotocol/agent-client-protocol/blob/5acaa3acda11e29d523193bfb3401c8497f5a90e/docs/protocol/v2/tool-calls.mdx#L323-L346)

规范没有 Pi/Maka 的 T1/T2 要求：没有“副作用前写 intent”、预分配结果 id、工具 replay safety 的双重判定、usage/cost ledger、writer lease、mutation line 或 crash-gate 测试协议。v2 还把 client 文件系统和 terminal 执行 API 移除，建议客户端能力通过 MCP server 提供；Agent-owned terminal 主要是 display-only。[`migration.mdx`](https://github.com/agentclientprotocol/agent-client-protocol/blob/5acaa3acda11e29d523193bfb3401c8497f5a90e/docs/protocol/v2/migration.mdx#L10-L16)

## 与 Jai 的映射

| ACP v2 | Jai 中可对应的角色 | 适合的语义 |
| --- | --- | --- |
| ACP Client | Desktop/Electron renderer 或外部 IDE | 用户交互、显示投影、权限选择 |
| ACP Agent | Jai Runtime Host / Agent runtime | 接受 prompt、执行模型和工具、发布 updates |
| `sessionId` | Jai Session identity | 连接/恢复时的外部 session 标识 |
| `session/prompt` | accepted input command | 进入 runtime 的输入请求；durable acceptance 仍由 Jai journal 定义 |
| `session/update` | message/tool/plan/usage read projection | 单向发送给 UI；不回写 canonical facts |
| `state_update` | live/in-memory run state | `running`/`requires_action`/`idle` 的客户端状态显示 |
| `session/resume` + replay | attach/reconnect projection | 重放客户端需要的历史，不等价于 operation recovery |

## 适配判断

### 适合放在边界层的部分

- **互操作**：把 Jai Runtime Host 暴露为 ACP Agent，或让 Jai Desktop 连接第三方 ACP Agent。
- **客户端投影**：将 canonical journal、operation reducer 和 live state 投影成 `session/update` 的消息、计划、tool call、usage 和状态更新。
- **连接生命周期**：使用 `initialize`、能力协商、`session/new/resume/list/close` 作为跨进程 attach/reconnect 的外层协议。
- **扩展隔离**：用 `_meta` 和 `_` 前缀自定义字段/方法，但必须经过显式白名单 DTO；代理或 replay 时保留未知值。[`extensibility.mdx`](https://github.com/agentclientprotocol/agent-client-protocol/blob/5acaa3acda11e29d523193bfb3401c8497f5a90e/docs/protocol/v2/extensibility.mdx#L6-L149)

### 不适合取代内部主协议的部分

1. **事实模型不同**：ACP update 是带 id 的 upsert/read model；Jai 的 session tree、operation log 和成本账本必须保持 append-only canonical facts。
2. **恢复语义不足**：ACP 的 resume/replay 没有定义 T1 intent、T2 outcome、预分配结果 identity、indeterminate 或 reconcile，因此不能证明“没有重复执行/没有丢副作用”。
3. **接受边界未定义为 durable commit**：`session/prompt` 返回空对象只说明 prompt 被 Agent 接受；何时写入 SQLite、如何跨崩溃恢复，仍需 Jai runtime 自己规定。
4. **权限 ownership 不同**：ACP 假设 Client 管理环境和权限 UI；Jai 不能因此把服务器的 workspace、project、审批和 durable policy 交还 renderer。
5. **transport 不完全匹配**：Jai 的 app/server 若使用 WebSocket/TLS，需要自建 ACP custom transport/adapter；官方 Streamable HTTP 尚是 draft，stdio 更像 subprocess 集成。
6. **成熟度风险**：v2 完整 surface 仍是 draft，Rust SDK 通过不稳定 feature 暴露；不能让内部唯一协议绑定未稳定的外部规范。

## 建议的最小落地

如果要支持 ACP，建议做一个薄 adapter，而不是重写 runtime：

1. 保持 SQLite journal、operation facts、recovery reducer 和权限 authority 在 Jai 内部。
2. 在 Runtime Host 边界实现 `initialize` + capability negotiation，再映射 `session/new/resume/list/close/prompt/cancel`。
3. 将 canonical facts 和 live state 单向投影为 ACP `session/update`；ACP update 不触发 journal 写入。
4. 对 `session/prompt` 的“accepted”定义内部 durable commit：只有写入 operation accepted/intent 后才向 ACP Client 返回成功接受。
5. 将 `requires_action` 映射到现有审批状态；权限结果回到 runtime command，不把 UI DTO 当作权限事实。
6. 用 `_meta` 放 Jai 专属的 session/run/operation identity 时，只发送白名单字段，例如 `sessionId`、`runId`、`operationId`、revision；禁止透传 `TaggedError.cause`、stack 或 SDK 原始错误。
7. 等 ACP v2 稳定后再扩大兼容面；在此之前保留 Jai 自己的 versioned internal envelope，避免把 draft surface 当作 durable storage contract。

## 最终判断

ACP v2 证明 Agent 生态正在收敛出一套通用的 **Agent↔Client 交互协议**：初始化、能力协商、session 生命周期、异步 prompt、权限请求和 UI updates。Pi/Maka 则在回答另一件事：**如何让运行事实可恢复、可审计、可验证**。

因此对 Jai 的正确分层是：

```text
Pi/Maka 风格 durable harness：内部事实、恢复与副作用语义
ACP v2：外部互操作、连接生命周期与客户端投影
```

把 ACP 当 adapter 可以缩短与 IDE/第三方 Agent 的互操作距离；把 ACP 当 canonical journal 则会丢失我们正在从 Pi/Maka 学到的最重要部分——intent-before-effect、indeterminate 和“状态由事实重新归约”。
