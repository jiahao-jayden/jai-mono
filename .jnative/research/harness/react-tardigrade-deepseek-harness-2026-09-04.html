React、Tardigrade 与 DeepSeek Harness：三个「可逆」语义的系统边界

厘清 React Render/Effect 分相、Tardigrade 日志驱动状态机与 DeepSeek Harness Reversible Effects 在系统层级中的真实物理边界，推导高可靠 Agent Harness 的持久化与容错取舍。

核验日期：2026-09-04 范围：React v19.2 · Tardigrade c338df7 · DSH 76fda72 查看 Markdown 证据笔记

背景与核心问题

在 Agent 架构讨论中，常常出现一种推论：既然 React 的 Effect 具备 Cleanup 机制，DeepSeek Harness 也宣称支持 Reversible Effects，那么 Agent 的工具调用与外部副作用就能够像前端状态一样被通用回滚。

React 的 Effect 有 cleanup → DeepSeek Harness 声明 reversible → 因此 Agent 的工具调用可以物理 rollback。

这种推论混淆了不同系统层级中的「可逆」语义。React 清理的是前端连接与订阅；DeepSeek Harness 回退的是插件装配生命周期与未确认物理写入；Tardigrade 依靠 Key 进行重放去重。三者在底层分层上处于完全不同的抽象维度，均不具备对外部世界副作用的通用撤销能力。

结论 01

React 的核心价值在于纯推导、受控提交与外部执行的三层分相。 其模型解释了内存计算为何可以安全重算与丢弃，但本身不提供持久化日志或跨进程故障恢复。

React 架构思想对 Agent Harness 的映射

1. 纯推导、受控提交与外部执行的三层隔离

React 的渲染管道严格分为纯 Render 计算、原子 Commit 提交与异步 Effect 同步三个阶段。计算阶段的纯函数特性使得渲染过程可以安全暂停与丢弃。搬到 Agent Harness 中，对应着清晰的三层边界：

已提交的不可变事实（Durable Facts / Event Log）
                   │
                   ▼
纯函数 Projection / Reducer（计算视图状态、权限结论、待执行 Action 与模型上下文）
                   │
                   ▼
受控 Commit（记录决策结果或前置执行意图）
                   │
                   ▼
外部 Executor（执行 LLM 推理、工具调用、文件修改与网络交互）
                   │
                   ▼
执行结果作为新的 Durable Event 追加落盘，进入下一轮推导

这种隔离保证了状态推导与决策重算绝不会意外触发外部工具，系统可基于历史事实进行确定性全量重放。

2. 单一事实源与最小推导状态

React 主张只持久化无法通过计算推导的最小状态集合。映射到 Agent 系统：运行期状态（当前视图、候选工具集、消息上下文）应始终作为持久化事件日志的只读投影，避免在数据库中维护多份易产生状态漂移的可变实体。

3. 确定性 Reducer 与稳定实体标识

React Reducer 将事件输入与状态计算解耦。在 Agent 中，权限判定、审批流转、恢复判定等确定性逻辑均应保持纯函数特性。同时，Session、Operation、Tool Invocation 必须具备全局唯一的稳定 Identity，这是跨崩溃重放去重与对账的基础。

4. Effect 作为同步边界与其非回滚性

React Effect 用于同步外部系统，Cleanup 仅能释放进程内资源（如取消订阅、关闭连接）。一旦外部操作产生持久影响（如写入磁盘、扣费 API 调用、发送邮件），Cleanup 无法实现业务回滚。Concurrent React 允许中断的也仅仅是 DOM Commit 前的纯计算，无法撤销已派发的外部调用。

Tardigrade：基于事件日志的持久化 Harness

Tardigrade 完整实践了「纯推导先于副作用」的模型，将不可变事件日志作为唯一事实源，建立了具备崩溃恢复能力的执行底座：

React 原则 Tardigrade 对应实现 补充的持久化语义 本质差异与边界
纯 Render Component 采用 initial → step → output，从 Event Log 投影出 State、View 与 Transitions 完整事件日志支持确定性重放；活跃运行时仅订阅 Tail 流 React Render 仅服务于内存虚拟树，无底层持久化事件日志
组件组合 子 View 通过代数合并，子 Transition 由 Reconciler 统一协调调度 多个子业务规则可基于同一份持久化事实独立推导欠缺的工作 组合本身不自动解决外部并发写入冲突与权限归属
Reconciliation Reconciler 过滤出尚未执行的 Transition，日志追加后作废快照重新计算 Transition Key 作为防重标识，已记录结果的操作不再重复触发 调度的是异步外部工作而非 DOM Patch；Transition 不等同于 useEffect
Effect 边界 ExternalEffect 在 Runtime 中调用外部服务并产出新事件落盘 步骤在触发后、落盘前崩溃时，Reconciler 重新派发执行（At-least-once） React Cleanup 不具备基于持久化 Key 的日志去重或幂等保证
Key / Identity Transition Key 严格对应持久化事件中的唯一标识 崩溃重启后能精准定位同一项工作与其输入参数 与 React 仅用于 UI 列表 Diff 的局部 Key 属于完全不同的概念

DeepSeek Harness「可逆」机制的具体层次

DeepSeek Harness 架构中所述的 Reversible Effects，其作用范围由具体上下文严格限定在三个层次：

  • Cordis 插件系统的生命周期治理：插件向上下文注册 Tool Schema、Prompt、Provider、Event Listener 等资源，卸载时由 Disposer 逆序注销，防止热重载或销毁后的资源泄漏。这是标准的依赖注入生命周期管理，不涉及业务日志回滚。
  • 未就绪临时状态的回滚：在 Agent 初始化失败时，未发布的临时 Scope 会被整体回收；在底层 JSONL 物理写入中断时，Adapter 会截断文件至上一个有效偏移量，防止脏读。
  • 已提交事实的只追加闭环：对于已写入 SessionEvent 的业务事实严格遵循只追加原则。崩溃恢复时在日志尾部合成 TOOL_OUTCOME_UNKNOWN 虚拟结果，将未知状态显式交由模型与用户决策。

对 JAI 架构演进的具体取舍

  1. 严格维持三层执行边界：业务逻辑必须显式归属于纯 Projection、持久化 Commit 或外部 Executor 之一。Projection 与 Reducer 保持纯函数特性，支持基于历史 Journal 进行随时无害的全量重放。
  2. 动作 Identity 与完成判据：参考 Tardigrade 的 Transition 模型，所有异步操作必须在派发前分配全局唯一的动作标识与前置记录，确保系统在恢复时能准确判定该步骤的状态。
  3. 插件生命周期与业务状态解耦：吸收 DSH 的 Cordis 模式，为 Extension 与 Connector 建立统一的 Disposer 注销链，使其生命周期独立于持久化业务日志。
  4. 坚持保守的未知状态恢复策略：对于崩溃时已派发但未落盘结果的工具调用，保持判定为 indeterminate_tool 并安全挂起。在下游工具未显式声明幂等协议前，绝不采用无条件的 At-least-once 重跑。
  5. 明确只读回放边界：调试 Trace、Session Fork 与历史 Replay 仅限于纯状态派生与已记录的观察结果，严禁向外部环境重复触发副作用。
