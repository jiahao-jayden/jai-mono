Electron Desktop 打包体积优化调研

JAI 的安装包大头来自 Electron 本身，最现实的缩小路径是裁剪应用层 runtime、原生依赖和前端语言资源。

类比：像行李箱里有一台固定大小的设备，再装入衣物和配件。换小衣物只能省掉配件部分，设备本身不会消失。这个类比在 Electron 多架构构建时会失效，因为同一箱子可能要同时装两套架构配件。

核验日期：2026-09-12。JAI 当前 macOS ARM64 zip 为 119701350 bytes；Electron Framework 约 271M；app.asar 约 14M；Resources/dist 约 24M。查看 Markdown 笔记

结论

优化顺序应该从应用真正带进去的文件开始，再处理压缩和更新机制。

类比：先把不该带的东西从搬家清单删掉，再压缩衣物，最后才研究快递是否支持分批寄送。压缩一个本来就不该带的箱子，收益很小。

Electron Framework 是固定底座，JAI 应先优化自身资源。

JAI 当前 Framework 约 271M，ASAR 和 runtime 只能影响应用层。官方性能文档

第一优先级是给 Desktop 设运行时白名单，只带实际启动需要的文件。

Signal 用 `files` 排除源码、测试、map 和通用 prebuild；Element 只把必要壳文件和独立 webapp 资源带入。Signal · Element

JAI 的 Desktop runtime 不必把 server/dist 的所有入口都复制进安装包。

当前 Desktop 启动 `Resources/dist/main.js`；其他 client entrypoint 和 stdio 入口应单独核验后排除。

原生模块必须匹配 Electron、操作系统和处理器架构，并放在可直接加载的位置。

粗暴排除 native 文件会出现构建成功但运行失败。Electron native ABI 文档

FFF 是 JAI 应用层里最明确的原生体积项，应该裁掉开发文件而保留 dylib 和目标架构 binding。

当前 `libfff_c.dylib` 约 9.7MB 未压缩，目录还包含 map、声明文件和 README。native module 收集案例

高亮语言资源应按产品实际支持范围加载。

JAI 当前前端 assets 约 13M、317 个文件；Signal 的生产构建明确启用 minify。Signal 构建配置

maximum 压缩不是主要体积优化手段。

electron-builder 的配置注释写明它通常没有明显体积收益，但会增加构建时间。配置注释

增量更新优化后续下载，NSIS-Web 优化架构选择，二者都不改变首装应用本体。

Windows Web Installer 会按架构下载对应 package；macOS 应继续比较单架构与 universal。NSIS-Web 文档

开源项目怎么做

成熟项目主要通过缩小构建输入、按平台筛依赖、隔离原生模块来控制体积。

类比：工厂给不同国家的订单装不同插头和说明书，而不是把所有版本都塞进每个箱子。这个类比不适用于 universal 包，因为 universal 的目的就是一箱兼容两种架构。

重复资源和 ASAR 边界

需要真实磁盘路径的文件要放在 ASAR 外，但同一个文件只能选择一个外置路径。

类比：需要拿出来使用的工具放工具箱旁边，但不能既放箱子里又放箱子外。这个类比不覆盖代码加载器的全部路径规则。

对 JAI 的建议顺序

先裁剪 Desktop runtime 和重复文件，再裁剪前端语言资源，最后评估压缩和更新。

类比：先减轻货物，再选择运输方式，最后安排补发。运输方式无法修复货物清单里多装的一整箱东西。

  1. 建立 Desktop 专用 runtime 目录，只复制 `main.js`、FFF 必需 node_modules 和实际资源。
  2. 对 FFF staged 目录做 allowlist，保留 dylib、ffi binding、必要 JS 和 package metadata。
  3. 审计 app.asar、Resources 和 app.asar.unpacked，确保大型文件只出现一次。
  4. 为 Shiki/代码高亮做语言 allowlist，并跑聊天、代码块、PDF、MCP/native smoke test。
  5. 最后比较 normal/maximum、首装 zip、解压 app、Framework 和更新 delta。

对本项目的影响

JAI 短期可以从应用层拿回数 MB 到十几 MB，几十 MB 的目标需要更换 Electron runtime。

类比：先把车里的货物和备件减掉能让车轻一些，但发动机的重量仍在那里。要换更小的发动机，属于换车方案。

JAI 当前约 120MB 的 zip 中，Framework 是主要固定成本；应用层约 38M。优先做 Desktop 专用 runtime、FFF allowlist、重复资源审计和高亮语言 allowlist。压缩级别、V8 snapshot 和增量更新分别针对构建时间、启动时间和后续更新下载量，不能代替文件裁剪。
