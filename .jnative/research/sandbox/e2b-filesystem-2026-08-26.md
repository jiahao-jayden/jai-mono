## 结论

1. `e2b@2.46.0` 的 `sandbox.files` 公共文件系统对象提供 `read`、`write`、`list`、`exists`、`makeDir`、`rename`、`remove`、`getInfo` 与 `watchDir`；其中 `getInfo` 是公开的 stat 等价物，底层调用 `Stat` RPC。各方法都能接收 `user`、`requestTimeoutMs` 与 `signal`（写入流例外见下文）。[SDK options](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/filesystem/index.ts#L259-L366) [方法实现](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/filesystem/index.ts#L829-L1119)
2. SDK **没有**暴露 `realpath`、canonical-path resolver 或可与后续操作绑定的符号链接解析能力。它只在 `getInfo`/`list` 的 `EntryInfo` 中暴露 symlink 的直接 `symlinkTarget`；这不是 canonical path，也不能消除远程 `getInfo` 与下一次读写之间的 TOCTOU。proto 的完整 `Filesystem` service 也没有这类 RPC。[`Filesystem` service](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/spec/envd/filesystem/filesystem.proto#L7-L20) [`EntryInfo.symlink_target`](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/spec/envd/filesystem/filesystem.proto#L53-L76)
3. 相对 `path` 按所选 `user` 的 home directory 解析；未给 `user` 时按 sandbox 默认用户解析。SDK 不提供 `cwd`/`base` 参数，并把输入字符串原样传给 HTTP `/files` 或 gRPC path 字段；已查 SDK 文件系统实现，没有 `path.normalize` 或 `path.resolve` 调用。E2B 后端是否另行规范化绝对路径，当前公开源码树中**查不到**，不能假设。[OpenAPI `FilePath`/`User`](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/spec/envd/envd.yaml#L323-L367) [`read` 的原样 query](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/filesystem/index.ts#L532-L546) [`StatRequest.path`](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/spec/envd/filesystem/filesystem.proto#L45-L51)
4. `list` 与 `getInfo` 返回的 `EntryInfo` 能区分 file/directory/symlink，并包含 `size`、`mode`、权限字符串、owner、group、`modifiedTime` 和 symlink target；JS SDK 将 proto `int64 size` 转为 JavaScript `number`。[`EntryInfo` 映射](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/filesystem/index.ts#L111-L145) [proto 字段](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/spec/envd/filesystem/filesystem.proto#L53-L85)
5. `read` 支持 `text`、`bytes`、`blob`、`stream`，其中 `stream` 返回 `ReadableStream<Uint8Array>`；`write` 支持 `string`、`ArrayBuffer`、`Blob`、`ReadableStream`，在非浏览器环境可走真正的流式 request body。源码与 OpenAPI 都**查不到**文件内容大小上限，不能据此断言服务端没有上限；可确认的 4 KiB 上限只针对 metadata xattr 总大小。[`read` overloads](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/filesystem/index.ts#L390-L570) [流式 write](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/filesystem/index.ts#L648-L743) [metadata 上限](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/spec/envd/envd.yaml#L240-L283)
6. `sandbox.files` 没有名为 `upload`/`download` 的方法，`write`/`read` 本身分别调用 `POST /files`/`GET /files`。但 `Sandbox` 另有 `uploadUrl` 与 `downloadUrl`，会生成可直接 HTTP 上传/下载的文件 URL；在 secured sandbox 中会把 path、read/write operation、user 和可选 expiry 签入 URL。它们不是 `Filesystem` 上的流式或原子写 API。[读写 HTTP 调用](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/filesystem/index.ts#L473-L569) [URL API](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/index.ts#L741-L844)
7. E2B 的独立文件系统 API 没有 `glob`、`grep` 或 `find`；在完整 `Filesystem` 类、filesystem proto 和 `/files` OpenAPI 中均查不到相应方法/RPC/endpoint。因此仅凭此文件系统 API 无法实现本项目的 `FileSearch`；需要另一个搜索或执行能力，本笔记不展开后者。[完整 `Filesystem` 类的起止](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/filesystem/index.ts#L371-L385) [结束位置](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/filesystem/index.ts#L1104-L1120) [proto RPC 枚举](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/spec/envd/filesystem/filesystem.proto#L7-L20)
8. 文件不存在会映射为 `FileNotFoundError`（但 `exists` 特意返回 `false`）；没有专用的 permission error，HTTP 500 的 OS permission-denied 和未映射的 gRPC `PermissionDenied` 都退回 `SandboxError`。普通 HTTP `requestTimeoutMs` 超时未统一包装为 E2B `TimeoutError`，而是保留运行时 fetch 的 abort reason；gRPC 的 `Canceled`、`DeadlineExceeded`、`Unavailable` 才映射到 E2B `TimeoutError`。[文件系统错误覆盖](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/filesystem/index.ts#L58-L83) [HTTP/Connect 映射](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/envd/api.ts#L24-L32) [gRPC timeout 映射](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/envd/rpc.ts#L69-L145)
9. 对本项目的 `FileSystem`/`FileSearch` 而言，E2B 可适配基础 stat、字节读取与流式读取、递归建目录，但缺少最关键的 canonical `resolvePath`、原子写、临时文件生命周期、`ReadableStream` 到接口声明 `AsyncIterable` 的适配、glob 和 grep。因此不能作为现有接口的无语义损失实现。[本项目接口](../../../packages/agent/src/harness/environment/types.ts) [E2B 读写与目录语义](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/filesystem/index.ts#L572-L819)

## realpath / 符号链接解析

结论是：**没有 canonical-path `realpath` API；有只读的直接 symlink target 信息。** 两者不能混为一谈。

`EntryInfo` 的 `type` 可为 `FileType.SYMLINK`，且 `symlinkTarget?: string` 载有“该 entry 是 symlink 时的 target”。这相当于在 `getInfo`/`list` 结果中提供一跳 `readlink` 信息；它没有返回 resolved/canonical path，也没有保证 target 位于某个 boundary 内。[SDK 类型与映射](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/filesystem/index.ts#L151-L180) [SDK entry mapping](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/filesystem/index.ts#L237-L254) [proto 原字段](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/spec/envd/filesystem/filesystem.proto#L53-L76)

为确认这个否定结论，逐字查阅了下列有限的 public/protocol surface：

- `packages/js-sdk/src/sandbox/filesystem/index.ts`：`Filesystem` 类从 `read` 开始到 `watchDir` 结束，没有 `realpath`、`resolve` 或 `readlink` 成员；其末尾在第 1120 行闭合。[类开始](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/filesystem/index.ts#L371-L390) [类结束](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/filesystem/index.ts#L1104-L1120)
- `packages/js-sdk/src/sandbox/filesystem/watchHandle.ts`：仅定义 watcher event/stop，不增加路径解析 API。[`WatchHandle`](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/filesystem/watchHandle.ts#L52-L152)
- `spec/envd/filesystem/filesystem.proto`：完整 service 仅有 `Stat`、`MakeDir`、`Move`、`ListDir`、`Remove`、`WatchDir` 与三个 watcher 管理 RPC；消息中没有 `RealpathRequest`、`ResolvePathRequest` 或等价 RPC。[完整 RPC 列表](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/spec/envd/filesystem/filesystem.proto#L7-L20)
- `spec/envd/envd.yaml` 的 `/files` HTTP contract：只有 file read/write endpoint 与 path/user/signature 参数；没有 path-resolution endpoint。SDK `read`/`write` 也只发送 `path` 与 `username`。[HTTP contract](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/spec/envd/envd.yaml#L214-L283) [SDK read](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/filesystem/index.ts#L484-L546) [SDK write](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/filesystem/index.ts#L705-L774)
- `packages/js-sdk/src/index.ts` 的 public exports 和 `packages/js-sdk/src/sandbox/index.ts` 的文件 URL helpers：前者只导出 `Filesystem` 相关类型/event 与 `getSignature`；后者只生成 read/write URL，并不解析路径。[exports](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/index.ts#L33-L47) [URL helpers](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/index.ts#L752-L844)

因此，调用方可以在客户端读取 `symlinkTarget` 后自行作字符串层面的多跳解释，但没有“服务器在同一次受约束操作中 resolve 且验证 boundary”的能力。`getInfo` 后到 `read`/`write`/`rename` 前，链接及其父路径仍可改变；这正是远程 TOCTOU 防线无法成立的缺口。该结论是由上述 API 缺失作出的接口层推论，**不是**对 envd 内核实现的猜测。

## 路径解析与规范化

HTTP OpenAPI 明确写明相对路径相对于 user's home：`"file.txt" resolves to ~/file.txt`；`username` 同时决定 file ownership 和相对路径解析，默认 sandbox default user。[`FilePath`/`User` 参数](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/spec/envd/envd.yaml#L323-L337) SDK 的 `FilesystemRequestOpts` 也直接说明 `user` 会影响 relative path resolution 和新建对象 owner。[`FilesystemRequestOpts`](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/filesystem/index.ts#L256-L266)

SDK 没有 `cwd`、`base`、`boundary`、`normalize` 或 `resolve` 选项。对 HTTP `read`/`write`，它将 caller 提供的 `path` 直接写进 query；对 gRPC `list`/`getInfo` 等也直接填入 proto path field。[HTTP path 传递](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/filesystem/index.ts#L484-L546) [gRPC path 传递](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/filesystem/index.ts#L829-L847) `EntryInfo.path` 只标为“Path to the filesystem object”，未声明 canonical；所以不能把它当作 `canonicalPath`。[`EntryInfo.path`](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/filesystem/index.ts#L89-L108)

## stat / list entry 结构

`getInfo` 和 `list` 均返回 `EntryInfo`。字段如下：

| 字段 | 含义与注意点 |
| --- | --- |
| `name`, `path` | 名称与服务端返回 path；没有 canonical 声明。 |
| `type?: FileType` | `FILE = 'file'`、`DIR = 'dir'`、`SYMLINK = 'symlink'`；要适配本项目时须把 `'dir'` 映射为 `'directory'`。 |
| `size: number` | proto 是 `int64`，SDK 用 `Number(entry.size)` 投影；源码没有对超过 JavaScript 安全整数范围的保护。 |
| `mode: number`, `permissions: string` | mode 权限位和如 `rwxr-xr-x` 的字符串。 |
| `owner`, `group` | 文件属主与属组。 |
| `modifiedTime?: Date` | proto timestamp 转 JS `Date`；本项目需转 `mtimeMs`。 |
| `symlinkTarget?: string` | 仅当 entry 是 symlink 时的直接 target，不是 canonical path。 |
| `metadata?: Record<string, string>` | `user.e2b.*` xattr 的投影。 |

字段定义和 proto 对照见 [`EntryInfo` SDK 类型](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/filesystem/index.ts#L111-L145)、[`mapEntryInfo`](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/filesystem/index.ts#L237-L254) 和 [proto `EntryInfo`](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/spec/envd/filesystem/filesystem.proto#L53-L85)。

## 读写、流与写入语义

### 读取

`read` 默认 `format: 'text'`；`'bytes'` 得到 `Uint8Array`，`'blob'` 得到 `Blob`，`'stream'` 得到 Web `ReadableStream<Uint8Array>`。SDK 的声明返回 `ReadableStream`，而本项目声明需要 `AsyncIterable<Uint8Array>`；适配层应显式转换或确认目标 runtime 的 async-iterator 兼容性。源码还要求调用方读完或取消 stream，以释放持有的连接。[overload 与 stream 生命周期说明](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/filesystem/index.ts#L398-L451) [stream 实现](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/filesystem/index.ts#L473-L529)

读取没有公开 range、chunk-size 或 maximum-bytes 选项。已检查 `FilesystemReadOpts`、`read` 实现和 `/files` OpenAPI；其中**查不到**文件内容大小限制或分段下载协议。这个“查不到”不等于服务端没有实际限额。[read options](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/filesystem/index.ts#L303-L319) [`GET /files`](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/spec/envd/envd.yaml#L214-L238)

### 写入

`write` 数据签名严格为 `string | ArrayBuffer | Blob | ReadableStream`，不直接接受 `Uint8Array`。非浏览器环境的 `ReadableStream` 默认选择 `application/octet-stream` 并可不经内存缓冲上传；浏览器走 `multipart/form-data`，而老 envd 会 fallback 到 multipart。[数据类型](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/filesystem/index.ts#L166-L169) [stream 选择](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/filesystem/index.ts#L648-L663) [上传 body](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/spec/envd/envd.yaml#L352-L367)

服务 contract 只说明上传会覆盖已有文件并保证父目录存在，没有 atomic replace、append、conditional write、mode preservation 或 transaction 承诺；SDK/proto 也没有这些选项。故不能把 `write` 或 `rename` 当作 `writeFileAtomic` 的证据。[`POST /files` 语义](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/spec/envd/envd.yaml#L239-L283) [`write` 文档](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/filesystem/index.ts#L572-L606)

文件内容的最大尺寸**查不到**。唯一确定的大小约束是 metadata：每个 key 最多 246 bytes，metadata 总大小最多 4096 bytes；这不是 file content limit。[metadata 限制](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/spec/envd/envd.yaml#L240-L260)

## 上传、下载与签名 URL

在 `Filesystem` 表面，`read` 与 `write` 已分别是 `/files` 的下载与上传：`GET /files` 的 OpenAPI summary 为 “Download a file”，`POST /files` 为 “Upload a file”。没有 `files.upload()` 或 `files.download()` 这两个独立方法。[endpoint 定义](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/spec/envd/envd.yaml#L214-L283) [SDK 调用处](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/filesystem/index.ts#L484-L546) [写调用处](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/filesystem/index.ts#L705-L774)

独立 URL helper 确实存在于 `Sandbox`：

- `uploadUrl(path?: string, opts?: SandboxUrlOpts): Promise<string>`：返回上传 URL，调用方以 multipart/form-data `POST` 到该 URL。
- `downloadUrl(path: string, opts?: SandboxUrlOpts): Promise<string>`：返回下载 URL。
- `SandboxUrlOpts` 为 `{ useSignatureExpiration?: number; user?: Username }`。secured sandbox 有 access token 时，helper 将 locally computed `signature` 和可选 `signature_expiration` 填入 URL；签名覆盖 `path`、`operation: 'read' | 'write'`、user、token 与可选过期时间。

这些签名参数也在 `/files` OpenAPI 中，但 public `FilesystemReadOpts`/`FilesystemWriteOpts` 没有接收它们；它们服务于 URL helper，而非在 `read`/`write` 调用中公开设置。[URL options 与 upload helper](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/index.ts#L38-L52) [`uploadUrl`/`downloadUrl`](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/index.ts#L741-L844) [signature 算法输入](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/signature.ts#L15-L60) [OpenAPI 参数](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/spec/envd/envd.yaml#L338-L350)

## glob / grep / find

**查不到独立 API。** `Filesystem` 类的完整方法范围和 proto 的全部 service RPC 均已在上文列出，其中没有 `glob`、`grep` 或 `find`；`/files` HTTP contract 仅是 GET/POST read/write。因而 E2B 文件系统 API 本身不支持按 pattern 枚举、文本匹配、结果 limit、context 或忽略大小写等 `FileSearch` 语义。[`Filesystem` public surface](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/filesystem/index.ts#L371-L1120) [proto surface](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/spec/envd/filesystem/filesystem.proto#L7-L153) [`/files` contract](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/spec/envd/envd.yaml#L214-L283)

若产品必须实现 `glob`/`grep`，需要在 E2B 文件系统 API 之外引入搜索能力；通常可由独立执行能力运行搜索程序，但该能力不属于本次调研范围，本文不对它的 API、PTY 或生命周期作结论。

## 错误类型/形状

| 情况 | HTTP read/write | gRPC list/stat/目录/rename/watch | 调用方含义 |
| --- | --- | --- | --- |
| 文件不存在 | HTTP 404 被 filesystem 专用 map 转为 `FileNotFoundError`。 | `Code.NotFound` 被专用 map 转为 `FileNotFoundError`；仅 `exists` 拦截该 code 并返回 `false`。 | 有专用错误；不能把 `exists: false` 与其他失败混淆。 |
| 权限不足 | OpenAPI 给出的本地 `permission denied` 示例是 HTTP 500；该 status 不在 default map，故包装为 `SandboxError('500: ...')`。若服务给 HTTP 403，同样落入 generic `SandboxError`。401 “invalid user” 则是 `AuthenticationError`。 | `Code.PermissionDenied` 未列在 default/custom map，所以走 generic `SandboxError('<code>: <message>')`。 | 没有 `PermissionDeniedError` 或稳定 errno 字段；只能从 `SandboxError` message/status 继续分类，契约较弱。 |
| 超时 | 普通 `read`/`write` 以 `AbortSignal.timeout(requestTimeoutMs)` 取消 fetch；SDK catch 仅在“连接被终止且 health probe 确认 sandbox 已死”时转 `TimeoutError`，其他 abort/timeout 原样抛运行时错误。stream 的握手/idle timer 明确以 `DOMException(..., 'TimeoutError')` abort。 | `Code.Canceled`、`Code.DeadlineExceeded`、`Code.Unavailable` 映射 `TimeoutError`。已建立的 `watchDir` 后续错误经 `onExit(err?)` 报告，而非原始 `watchDir` promise。 | HTTP timeout 的类型不跨 runtime 稳定；需要 adapter 自行归一化。 |

证据：filesystem 的 404/NotFound override 见 [`index.ts#L58-L83`](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/filesystem/index.ts#L58-L83)，`exists` 特例见 [`#L970-L992`](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/filesystem/index.ts#L970-L992)。HTTP map/fallback 见 [`envd/api.ts#L24-L32`](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/envd/api.ts#L24-L32) 与 [`#L100-L140`](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/envd/api.ts#L100-L140)；OpenAPI 的 permission-denied 示例与 401/404/500/507 返回见 [`envd.yaml#L400-L444`](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/spec/envd/envd.yaml#L400-L444)。gRPC map/fallback 见 [`envd/rpc.ts#L69-L145`](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/envd/rpc.ts#L69-L145)，HTTP timeout signal 与 stream timeout reason 见 [`connectionConfig.ts#L102-L123`](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/connectionConfig.ts#L102-L123) 和 [`#L162-L229`](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/connectionConfig.ts#L162-L229)。

## 对本项目的影响

对照目标为 [`packages/agent/src/harness/environment/types.ts`](../../../packages/agent/src/harness/environment/types.ts) 中的 `FileSystem` 与 `FileSearch`（不讨论 `Shell`）。

| 本项目接口 | E2B 支撑情况 | 映射与具体缺口 |
| --- | --- | --- |
| `resolvePath(input, { base, boundary, mustExist, expectedKind })` | **不支撑** | 没有 `base`、`boundary`、`mustExist`、`expectedKind` 或 canonical 输出；`getInfo` 的 `symlinkTarget` 只是单跳 target，无法给出原子/受边界约束的 `canonicalPath`。先 stat 再操作会留下远程 TOCTOU。[proto RPC](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/spec/envd/filesystem/filesystem.proto#L7-L20) [symlink 字段](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/spec/envd/filesystem/filesystem.proto#L53-L76) |

| `grep({ cwd, target, pattern, include?, ignoreCase?, literal?, context?, limit })` | **不支撑** | 不存在 SDK/proto/HTTP 文本搜索 API，无法产生 line/context rows、matches 或 limitReached。[proto RPC](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/spec/envd/filesystem/filesystem.proto#L7-L20) [`/files`](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/spec/envd/envd.yaml#L214-L283) |

综上，若目标是保持当前接口的安全语义，最先决的阻塞项是 `resolvePath` 的 canonical/boundary 能力：E2B 的相对 home-dir 规则与可读 symlink target 不构成替代品。基础文件读写可以另写薄 adapter，但必须显式降级或补充外部机制，不能把它宣称为满足现有 `FileSystem`/`FileSearch` contract。
