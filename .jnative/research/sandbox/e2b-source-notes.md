## Conclusions

1. **No SDK-native canonical-path operation exists.** The entire filesystem gRPC service lists only `Stat`, `MakeDir`, `Move`, `ListDir`, `Remove`, and `WatchDir`; neither it nor the JS `Filesystem` public methods expose `realpath`/`readlink`/path canonicalization. `EntryInfo` reveals a symlink's *textual target*, but not a resolved canonical path. ([filesystem RPC surface](https://github.com/e2b-dev/infra/blob/e19a12b8fc5d318c6e88a8edba0a94d1f153a841/packages/envd/spec/filesystem/filesystem.proto#L7-L20), [entry fields](https://github.com/e2b-dev/infra/blob/e19a12b8fc5d318c6e88a8edba0a94d1f153a841/packages/envd/spec/filesystem/filesystem.proto#L53-L76), [JS `Filesystem` methods](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/filesystem/index.ts#L398-L457))
2. **That makes E2B an incomplete direct implementation of an environment contract whose client must enforce `resolvePath` with symlink-safe, TOCTOU-resistant boundary checks.** Shelling out to `realpath` is possible because command execution invokes `/bin/bash -l -c`, but it splits resolution from later file operations and therefore is not an atomic capability boundary. ([command launch implementation](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/commands/index.ts#L426-L485))
3. **The remaining basic filesystem operations map closely:** reads support text, bytes, Blob and web `ReadableStream`; writes accept string, `ArrayBuffer`, Blob or `ReadableStream`; stat/list return type/size/mode/mtime and a symlink target; and directory watching is callback-and-handle based. None of these sources exposes a native glob, grep, `realpath`, or atomic-write primitive. ([read overloads](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/filesystem/index.ts#L387-L457), [write overloads and formats](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/filesystem/index.ts#L572-L606), [entry mapping](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/filesystem/index.ts#L237-L254), [filesystem RPC surface](https://github.com/e2b-dev/infra/blob/e19a12b8fc5d318c6e88a8edba0a94d1f153a841/packages/envd/spec/filesystem/filesystem.proto#L7-L20))
4. **Background commands are durable server-side processes rather than request-scoped tasks.** `run(..., { background: true })` returns a `CommandHandle`; `disconnect()` explicitly does not kill its process; `list()` and `connect(pid)` allow a later caller to find and reconnect by PID; and stdin can be sent repeatedly by PID after starting with `stdin: true`. ([run overloads](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/commands/index.ts#L374-L424), [disconnect/reconnect contract](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/commands/commandHandle.ts#L184-L198), [list/connect/send stdin](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/commands/index.ts#L160-L233), [stdin integration test](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/tests/sandbox/commands/sendStdin.test.ts#L4-L23))
5. **Output is live callback delivery, not a resumable log interface.** The public JS surface takes `onStdout`/`onStderr` callbacks and accumulates strings on the handle; its `ConnectRequest` includes only a PID or tag selector, with no output cursor, sequence number, or history-fetch RPC. The SDK explicitly stops receiving events after disconnect. Whether the envd server retains and replays output produced in a disconnect gap is **could not verify** without the infra runtime source; a portable adapter must not rely on replay. ([output callbacks](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/commands/index.ts#L44-L100), [handle event processing](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/commands/commandHandle.ts#L270-L374), [process protocol](https://github.com/e2b-dev/infra/blob/e19a12b8fc5d318c6e88a8edba0a94d1f153a841/packages/envd/spec/process/process.proto#L69-L105), [selector shape](https://github.com/e2b-dev/infra/blob/e19a12b8fc5d318c6e88a8edba0a94d1f153a841/packages/envd/spec/process/process.proto#L162-L171))
6. **Sandbox pause is a real stateful checkpoint.** Default `pause()` retains a full memory snapshot; an integration test shows a background PID survives pause/resume and can be reconnected. With `keepMemory: false`, E2B preserves the filesystem but cold-boots on resume, losing processes and open connections. `connect()` resumes a paused sandbox and test coverage asserts the sandbox ID stays unchanged. ([pause options](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/sandboxApi.ts#L506-L520), [memory-pause process test](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/tests/sandbox/snapshot.test.ts#L84-L105), [filesystem-only test](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/tests/sandbox/snapshot.test.ts#L166-L205), [same-ID test](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/tests/sandbox/snapshot.test.ts#L5-L18))
7. **Command `timeoutMs` is attached to the Start/Connect streaming RPC, while `kill` is a distinct `SendSignal(SIGKILL)` operation.** The SDK's timeout-error cleanup aborts its local stream/controller and does not call `kill`; however, the authoritative envd runtime behaviour when a client-side stream deadline elapses is **could not verify** because the infra runtime was not retrievable. Do not state categorically that a timed-out command is killed or survives server-side on this evidence alone. ([command timeout option](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/commands/index.ts#L73-L100), [Start stream and cleanup path](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/commands/index.ts#L439-L485), [kill path](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/commands/index.ts#L272-L311), [protocol distinction](https://github.com/e2b-dev/infra/blob/e19a12b8fc5d318c6e88a8edba0a94d1f153a841/packages/envd/spec/process/process.proto#L5-L20))

### Semantics and limits

- File-path API documentation says a relative file path resolves against the selected user's home directory; the user parameter defaults to the sandbox default user. `FilesystemRequestOpts.user` says this user affects relative-path resolution and ownership. ([envd file-path parameter](https://github.com/e2b-dev/infra/blob/e19a12b8fc5d318c6e88a8edba0a94d1f153a841/packages/envd/spec/envd.yaml#L323-L337), [SDK options](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/filesystem/index.ts#L256-L266))
- `EntryInfo` distinguishes `file`, `dir`, and `symlink`; it contains `size`, numeric `mode`, `permissions`, owner/group, optional `modifiedTime`, and optional `symlinkTarget`. The protocol represents the timestamp and symlink target fields and the SDK maps them to `Date` and `symlinkTarget`. ([SDK type](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/filesystem/index.ts#L86-L164), [wire entry](https://github.com/e2b-dev/infra/blob/e19a12b8fc5d318c6e88a8edba0a94d1f153a841/packages/envd/spec/filesystem/filesystem.proto#L53-L76), [mapping](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/filesystem/index.ts#L237-L254))
- `read({format: 'stream'})` returns a web `ReadableStream<Uint8Array>` whose request timeout only bounds handshake; after handshake it persists until consumed/cancelled/error/idle timeout. This is not declared as the project's desired `AsyncIterable` API, though an adapter in a Node runtime may bridge a web stream to async iteration. ([stream read contract](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/filesystem/index.ts#L433-L451), [stream lifecycle code](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/filesystem/index.ts#L473-L529))
- `write` creates missing parents and overwrites an existing file. It can stream an octet-stream upload outside browsers when given a `ReadableStream`. **Atomic replacement is not promised or exposed; could not verify atomic write semantics from the SDK/protocol source.** ([write contract](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/filesystem/index.ts#L572-L592), [streamed-upload path](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/filesystem/index.ts#L648-L744), [infra upload contract](https://github.com/e2b-dev/infra/blob/e19a12b8fc5d318c6e88a8edba0a94d1f153a841/packages/envd/spec/envd.yaml#L214-L283))
- There is no filesystem `glob`/`grep` RPC or JS method in the exhaustive service list. An implementation must either enumerate/filter client side or call a shell command such as `rg`/`find` through `commands.run`; availability of a specific binary in a template was **not found** in source. ([filesystem service](https://github.com/e2b-dev/infra/blob/e19a12b8fc5d318c6e88a8edba0a94d1f153a841/packages/envd/spec/filesystem/filesystem.proto#L7-L20), [shell launch](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/commands/index.ts#L447-L464))

## Lifecycle

- `Sandbox.create()` creates a sandbox with a 300,000 ms default lifetime. `Sandbox.connect(id)` returns a running sandbox and automatically resumes one that is paused; public `Sandbox.pause()` returns `Promise<boolean>` and public `Sandbox.kill()` returns `Promise<boolean>`. ([default](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/connectionConfig.ts#L8-L10), [create/connect](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/index.ts#L251-L395), [kill/pause](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/index.ts#L621-L668))
- There is no current public `Sandbox.resume()` method in the JS SDK. The pinned control plane still has a deprecated `POST /sandboxes/{sandboxID}/resume`; use `connect()` in this SDK. ([deprecated endpoint](https://github.com/e2b-dev/infra/blob/e19a12b8fc5d318c6e88a8edba0a94d1f153a841/spec/openapi.yml#L2739-L2779), [SDK connect implementation](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/index.ts#L467-L476))
- `pause()` defaults to `keepMemory: true`. Memory-preserving pause retains running process state in the observed integration test; the filesystem-only option retains filesystem state but restarts the VM and loses process/open-connection state. Resume retains the sandbox ID in the corresponding integration tests. ([pause option](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/sandboxApi.ts#L506-L520), [process survival test](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/tests/sandbox/snapshot.test.ts#L84-L105), [filesystem-only test](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/tests/sandbox/snapshot.test.ts#L166-L205))
- SDK comments specify maximum lifetimes of 24 hours for Pro and one hour for Hobby, both on creation and `setTimeout`. The source examined does not show plan/entitlement enforcement code, so server-side rejection behaviour for over-limit values is **could not verify**. ([create timeout](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/sandboxApi.ts#L590-L596), [set timeout](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/index.ts#L576-L599))
- Self-hosting is explicitly documented in the repository README as Terraform-deployed infrastructure; the source marks AWS and GCP as supported and Azure/general Linux as unchecked. A GA/Beta label for self-hosting was **not found** in the examined source. ([self-hosting section](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/README.md#L87-L95))

## Consequences for this project's environment protocol

1. The project's `resolvePath -> operation` invariant cannot be preserved using E2B's filesystem API alone. `getInfo` detects a symlink and reports its textual target, but there is no canonical-result RPC and no way to bind a checked resolution to the subsequent read/write operation. A separate host-defined path policy or an E2B-side privileged service operation would be required; a preflight `commands.run('realpath ...')` is TOCTOU-prone. ([symlink fields](https://github.com/e2b-dev/infra/blob/e19a12b8fc5d318c6e88a8edba0a94d1f153a841/packages/envd/spec/filesystem/filesystem.proto#L53-L76), [filesystem RPC surface](https://github.com/e2b-dev/infra/blob/e19a12b8fc5d318c6e88a8edba0a94d1f153a841/packages/envd/spec/filesystem/filesystem.proto#L7-L20))
2. `readFileChunks` can be adapted from E2B `read({ format: 'stream' })`, but the adapter must translate a web `ReadableStream<Uint8Array>` to the project's `AsyncIterable` and define retry/cancellation semantics. E2B itself holds the connection until the stream is consumed/cancelled/errors. ([stream return type](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/filesystem/index.ts#L433-L451), [connection cleanup](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/connectionConfig.ts#L250-L330))
3. `writeFileAtomic` does not map cleanly: E2B offers direct overwrite/create upload and `rename`, but no documented atomic replacement or temporary-file handle. The project's `createTempFile` handle (`append`/`remove` lifecycle) has no E2B equivalent and would require an adapter-owned remote path plus explicit cleanup, with failure/recovery semantics defined by this project. ([write semantics](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/filesystem/index.ts#L572-L606), [rename](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/filesystem/index.ts#L899-L937))
4. `glob`/`grep` need a shell-based or client-side adapter, adding RPCs beyond the local environment's direct calls. `Bash` can stream to callbacks and reconnect to a running PID, but it cannot promise lossless output after reconnection from the available API; process durability is compatible only when preserving the PID and explicitly modelling possible output gaps. ([lack of filesystem search RPCs](https://github.com/e2b-dev/infra/blob/e19a12b8fc5d318c6e88a8edba0a94d1f153a841/packages/envd/spec/filesystem/filesystem.proto#L7-L20), [command reconnect](https://github.com/e2b-dev/E2B/blob/d42686d982f741b01f2c71da304e63846b34706f/packages/js-sdk/src/sandbox/commands/index.ts#L313-L372), [no output cursor](https://github.com/e2b-dev/infra/blob/e19a12b8fc5d318c6e88a8edba0a94d1f153a841/packages/envd/spec/process/process.proto#L69-L105))
