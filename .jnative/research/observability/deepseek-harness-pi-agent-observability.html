DeepSeek Harness 与 Pi Agent 如何做 Agent 观测和日志收集

问题：两套 Agent 如何把运行时事实送入本地 durable store、用户界面与远端 exporter；哪些能力是当前真实接线，哪些只是可选或尚未接入。

直接结论

HTML 仅呈现证据笔记已有结论

  1. 结论 01 · 事实模型

    DeepSeek 用单一 append-only SessionEvent ledger 驱动持久化、UI、查询与遥测；Pi 当前 CLI 把 live 事件与 durable v3 对话树分开。

    查看来源

  2. 结论 02 · 轨迹粒度

    DeepSeek 本地保存 turn、step 与 normalized chunks；Pi 的 message/tool update 只 live，v3 session 主要保存最终消息与分支事实。

    查看来源

  3. 结论 03 · 远端观测

    DeepSeek 已接入 OTel Logs，但没有 Agent traces/metrics；Pi 的 span schema 已发布，production instrumentation 与 exporter 尚未接入。

    查看来源

  4. 结论 04 · DeepSeek 外发

    OTel 每个 step 只投影第一条 chunk；另有可发送完整 canonical suffix 的 dsh_session_log，但默认关闭，送达语义也不同。

    查看来源

  5. 结论 05 · Pi 存储状态

    Pi v4 JSONL 与 SQLite backend 已真实实现，却未接入当前 Coding Agent CLI；当前默认仍是 v3 JSONL，Harness runtime 仍未完成。

    查看来源

  6. 结论 06 · Pi 边界修正

    Pi 默认不上传 Agent spans，却仍有模型目录、版本、package 与条件性 install 网络行为；部分 provider diagnostics 的 stack 可随最终 assistant message 持久化。

    查看来源

  7. 结论 07 · shell 与错误

    DeepSeek shell 有 per-stream capture spill 与通用 tool-result spill 两层；Pi stdout/stderr 默认进入同一字节流。两者都不能把临时全文路径视为长期可审计 artifact。

    查看来源

对 jai-mono 的影响

  1. 坚持 SQLite journal 是唯一 durable owner，从 journal 与 live state 单向投影。
  2. 分开 durable facts、live events、diagnostic logs 与 traces/metrics，并写明 replay、背压和失败隔离。
  3. shell 保存结构化 channel/seq/monotonic offset 与 durable artifact reference，合并文本只作模型投影。
  4. 远端 telemetry 使用白名单 DTO，默认排除内容、headers、cwd、stack、cause 与 SDK error object。
  5. 以最终 composition root 测试 endpoint、默认关闭、hard opt-out、redaction 与 shutdown。
  6. 先完成本地审计 UI；远端关系用 spans、聚合分布用 metrics，可靠上传需明确 outbox 语义。

尚未确认

  • DeepSeek collector 的服务端 schema、留存、访问控制、地域、二次处理与删除政策。
  • 部署方自定义 DeepSeek 插件或 Pi Extension / transport 产生的额外采集与网络行为。
  • Pi v4/Harness 未来何时接入 Coding Agent CLI；规格与已实现 adapter 不代表当前运行事实。
