在构建持久化会话（`session: { kind: "new" | "resume" }`）时，宿主必须向 SDK 提供一个存储驱动。SDK 导出了接口契约 `CodingSessionStore` 与开箱即用的内存参考实现 `InMemorySessionStore`。

```ts
import {
  type CodingSessionStore,
  InMemorySessionStore,
  SessionConflictError,
  type CodingAgentFileCapabilities,
} from "@jai/coding-agent";
```

---

## `InMemorySessionStore`（内存存储实现）

`InMemorySessionStore` 是 SDK 自带的完全基于内存的 SessionStore 实现，适合测试环境、本地调试或短期自动化作业：

```ts
const store = new InMemorySessionStore();

const created = await createCodingAgent({
  model: "anthropic/claude-3-7-sonnet",
  cwd: process.cwd(),
  session: {
    kind: "new",
    id: "session-test-01",
    store,
  },
  fileCapabilities: {
    homeDirectory: process.env.HOME ?? "",
    workspaceDirectory: process.cwd(),
    workspaceTrusted: true,
  },
});
```

### 内部特性
- **数据结构**：内部基于 `Map<string, StoredSession>` 保存所有会话记录。
- **快照隔离**：所有的读取与写入均使用 `structuredClone()` 进行深拷贝，防止外部对象引用引起状态意外突变。
- **并发乐观锁**：在调用 `append` 追加日志条目时，若当前内存中的版本（`revision`）与入参 `expectedRevision` 不符，自动抛出标准 `SessionConflictError`。
- **生命周期局限**：数据随当前进程退出而完全释放，**不具备跨重启持久化能力**。生产环境建议使用数据库存储（参见 [生产级 SQLite 存储实战](/docs/guides/sqlite-store)）。

## `CodingSessionStore`（存储驱动契约）

任何希望为 SDK 提供持久化能力的外部存储（如 SQLite、PostgreSQL、LevelDB），必须实现以下四个异步方法：

```ts
export interface CodingSessionStore<TAppState extends JsonObject = JsonObject> {
  /** 根据会话 ID 读取整条会话记录；不存在时返回 undefined */
  load(id: string): Promise<StoredSession<TAppState> | undefined>;

  /** 仅当会话不存在时创建新记录，返回初始版本号 revision（如 UUID 或 Hash） */
  create(id: string, appState: TAppState): Promise<string>;

  /**
   * 向指定会话按顺序追加一条 Journal Entry。
   * 必须严格校验 expectedRevision：若版本冲突，必须抛出 SessionConflictError。
   * 写入成功后返回生成的新版本号 revision。
   */
  append(id: string, entry: SessionEntry<TAppState>, expectedRevision: string): Promise<string>;

  /** 删除指定会话记录 */
  delete(id: string): Promise<void>;
}
```

### 关联数据结构

#### `StoredSession`
```ts
export interface StoredSession<TAppState extends JsonObject = JsonObject> {
  readonly id: string;
  readonly revision: string;             // 当前会话的乐观锁修订版本标识
  readonly initialAppState: TAppState;    // 初始应用状态
  readonly entries: readonly SessionEntry<TAppState>[]; // 按顺序追加的全部 Journal 条目
}
```

#### `SessionConflictError`
当发生版本冲突（例如另一个并发进程或前台操作已经向该会话提交了新条目导致 `expectedRevision` 过期）时抛出的结构化异常：
```ts
export class SessionConflictError extends TaggedError("session.conflict")<{
  readonly cause?: unknown;
  readonly message: string;
}> {}
```

## `CodingAgentFileCapabilities`（文件权责边界）

在配置持久化会话（`new` 或 `resume`）时，除了 `store` 之外，宿主还必须提供 `fileCapabilities` 声明本地文件与配置系统的物理边界：

```ts
export interface CodingAgentFileCapabilities {
  /** 用户家目录路径：用于寻找全局用户设置（~/.jai/settings.json） */
  readonly homeDirectory: string;

  /** 当前工作区物理绝对路径：用于定位项目级配置与本地资源 */
  readonly workspaceDirectory: string;

  /** 是否信任该工作区（设置为 true 时才允许加载项目级规则与扩展配置） */
  readonly workspaceTrusted: boolean;
}
```

若在持久会话模式下遗漏此字段，`createCodingAgent` 将在初始化阶段直接返回 `coding_sdk.file_capabilities_required` 错误。

## 辅助快照工具

SDK 还导出了会话日志的折叠与初始化辅助函数：

- **`emptySnapshot(appState, createdAt)`**：根据初始应用状态构造一个干净的 `SessionSnapshot` 结构。
- **`applyEntry(snapshot, entry)`**：纯函数，将一条新的 `SessionEntry`（消息、状态更新、压缩记录）折叠进旧快照，生成更新后的快照对象。
- **`emptyPersistedCodingSessionState()`**：快速生成一个包含空状态的持久化会话模板。
