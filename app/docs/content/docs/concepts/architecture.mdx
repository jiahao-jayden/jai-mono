Jai 采用清晰的单向分层架构，将业务交互、Agent 执行控制、底层循环与模型通信解耦为独立的职责层次：

```text
┌─────────────────────────────────────────────────────────────┐
│ 宿主应用（Host：Desktop、CLI、评测 Harness）                  │
│ 用户交互界面、本地设置解析、持久化存储适配、审批 UI           │
└──────────────────────────────┬──────────────────────────────┘
                               │ createCodingAgent({ ... })
┌──────────────────────────────▼──────────────────────────────┐
│ @jai/coding-agent（公开 SDK）                                │
│ 对外暴露的业务接口：Agent 状态机、内置工具集、权限规则求值    │
└──────────────────────────────┬──────────────────────────────┘
                               │ 内部调用
┌──────────────────────────────▼──────────────────────────────┐
│ @jai/agent（Agent 核心引擎）                                 │
│ 循环状态机（Agent Loop）、上下文压缩、日志与快照演进          │
└──────────────────────────────┬──────────────────────────────┘
                               │ 内部调用
┌──────────────────────────────▼──────────────────────────────┐
│ @jai/ai（模型适配层）                                        │
│ 统一请求与响应协议、流式事件派发、Token 与推理规范化          │
└─────────────────────────────────────────────────────────────┘
```

## 核心原则：产品配置归宿主所有

SDK 专注于提供通用的 Agent 执行能力，避免掺杂特定产品的业务假设：

- **配置持久化路径**：诸如 `~/.jai/settings.json` 等配置文件路径规范由宿主应用维护。SDK 仅从宿主传入的纯 JavaScript 对象读取配置项，不直接在底层隐式读取本地文件系统。
- **模型目录与凭据发现**：宿主负责扫描本地环境、验证提供商可达性，最终把确认可用的模型名称（如 `anthropic/claude-3-7-sonnet`）与凭据传入 SDK。
- **持久化驱动解耦**：SDK 定义了基于 Journal 的存储契约 `CodingSessionStore`。Desktop 使用内嵌 SQLite 存储会话，轻量工具可使用文件或内存，SDK 自身不绑定特定数据库引擎。
- **审批交互解耦**：SDK 负责对工具调用与执行参数进行安全校验与风险评级；当需要用户授权时，通过回调函数触发宿主自定义的 UI 确认窗口或终端交互。

这种设计使得同一套 SDK 能无缝服务于 Electron 桌面客户端、无头自动化 CLI 和云端评测流水线。

## 数据流与单向投影

在一次常规的任务调用（`agent.prompt(...)`）中，数据流严格遵循确定性路径：

1. **输入阶段**：宿主提交提示词，触发扩展的 `beforeAgentStart` 钩子，完成输入预处理。
2. **推理阶段**：模型适配层组装上下文并向大模型发起流式请求，捕获原始响应增量并映射为统一事件。
3. **工具评估**：模型发起工具调用请求后，权限引擎根据配置规则进行静态分析与路径边界检查；若触发敏感行为，唤起宿主审批回调。
4. **工具执行**：执行内置工程工具或扩展工具，捕获结果并包装为标准的工具响应消息。
5. **状态汇总**：循环进入下一轮或收尾。会话状态由底层日志（Journal）单向投影生成，向调用方提供不可变的状态快照。
