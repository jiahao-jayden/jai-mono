---
title: 创建配置
description: 理解 createCodingAgent 的模型、目录、session、权限、工具与 extension 配置。
---

`createCodingAgent()` 直接接收公开配置，不需要先构造 Host。产品级配置由 Desktop、CLI 或你的应用在调用前解析；传给 SDK 的只有执行本次 Agent 所需的最小数据。

## 最小配置

```ts
import { createCodingAgent } from "@jai/coding-agent";

const created = await createCodingAgent({
  model: "openai/gpt-4.1-mini",
  cwd: process.cwd(),
  session: { kind: "ephemeral" },
  permissionMode: "plan",
});
```

`model` 必须使用 `<provider>/<model>`：provider 为 `anthropic`、`openai` 或 `openai-compatible`。`cwd` 省略时默认为 `process.cwd()`；`session` 省略时使用 ephemeral session。

## Provider 配置

默认凭据来自环境变量。需要独立 key、兼容服务地址或自定义 header 时传入 `provider`：

```ts
const created = await createCodingAgent({
  model: "openai-compatible/local-model",
  provider: {
    baseUrl: "http://127.0.0.1:8080/v1",
    authentication: "none",
  },
  cwd: process.cwd(),
});
```

`anthropic` 只支持 `x-api-key` 认证；`openai` 和 `openai-compatible` 支持 `bearer` 或 `none`。`baseUrl` 必须是 HTTPS，或没有用户名和密码的 loopback HTTP URL。

## 调用方可控制的行为

- `session`：选择 `new`、`resume` 或 `ephemeral`，并为 durable session 提供目录。
- `permissionMode` 和 `requestApproval`：选择默认安全策略，并在需要时请求用户决定。
- `tools` / `excludeTools`：选择内置工具；`excludeTools` 在重叠时优先。
- `extensions`：提供自定义工具、skills、hooks 以及它们的释放逻辑。
- `maxTurns`、`instructions`、`compactionSummaryInstructions`：控制单次执行与 prompt 组成。

模型目录、Jai config、Agent Plugin 的发现与装配、Connector client 及其 UI 都不是 root SDK 参数。它们属于各宿主的业务层，宿主可把最终结果投影为 `model`、`provider`、`extensions` 和 `requestApproval`。
