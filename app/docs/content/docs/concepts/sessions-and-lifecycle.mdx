---
title: 会话
description: ephemeral、new 与 resume 三种会话模式，以及基于 Journal 的持久化机制。
---

SDK 的会话系统负责维护 Agent 的上下文历史、工具执行记录、中间产物与状态演进。会话生命周期由 `session` 字段指定：

```ts
export type CodingSessionSelection =
  | { readonly kind: "ephemeral" }
  | { readonly kind: "new"; readonly id?: string; readonly store: CodingSessionStore }
  | { readonly kind: "resume"; readonly id: string; readonly store: CodingSessionStore };
```

## 三种会话模式

| 模式 | 适用场景 | 依赖要求 | 生命周期特征 |
|---|---|---|---|
| `ephemeral` | 快速单次任务、代码审查、一次性脚本执行 | 无需额外配置 | 在隔离的临时文件夹中运行，`close()` 时自动全量销毁 |
| `new` | 新建多轮对话、交互式任务、需要中断恢复的长期项目 | 需提供 `store` 与 `fileCapabilities` | 生成唯一的 `sessionId`，操作流水按 Append-only Journal 持久化 |
| `resume` | 重新连接已有对话、跨应用重启恢复上下文 | 需提供已记录该 ID 的 `store` 与 `fileCapabilities` | 自动回放历史 Journal 并重建状态，无缝继续会话 |

## 持久化会话要求

启用 `new` 或 `resume` 模式时，宿主必须同时提供以下两项核心参数：

### 1. 存储驱动（`store: CodingSessionStore`）
`CodingSessionStore` 负责以追加写入（Append-only）的形式保存每一次会话条目（Entry）。条目包括用户输入、模型响应、工具副作用、上下文压缩摘要与分支记录。

SDK 导出了轻量的内存实现 `InMemorySessionStore` 用于开发与测试。在实际生产场景中，宿主通常实现基于 SQLite 或数据库的 Store 适配器。

### 2. 本地文件权责（`fileCapabilities`）
明确应用与项目的根路径，确立安全隔离与本地资源可见性：

```ts
const fileCapabilities: CodingAgentFileCapabilities = {
  // 用户家目录路径：用于存储全局配置
  homeDirectory: "/Users/username",
  // 项目工作区路径：用于存放项目级配置与本地资源
  workspaceDirectory: "/Users/username/projects/my-app",
  // 是否信任该工作区（信任后才允许读取项目级配置规则）
  workspaceTrusted: true,
};
```

## 会话状态与查询

Agent 实例在运行过程中提供实时的只读状态：

- `agent.sessionId`：会话的全局唯一标识。
- `agent.state`：不可变的状态快照对象（包含消息流 `messages`、当前待办 `todos`、文件产物 `artifacts`、当前运行状态 `status`）。该属性是一个 Getter，每次读取时基于内部状态机即时投影。
- `agent.close()`：优雅关闭当前会话。执行中的任务将被安全取消，等待未写入的 Journal 落盘，并销毁挂载的扩展插件。
