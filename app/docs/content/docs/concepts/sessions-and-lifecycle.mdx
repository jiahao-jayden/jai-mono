---
title: Sessions 与生命周期
description: 选择 durable 或 ephemeral session，并在宿主生命周期结束时安全关闭 Agent。
---

`CodingSessionSelection` 有三种形式：

```ts
{ kind: "new", store: CodingSessionStore, id?: string }
{ kind: "resume", id: string, store: CodingSessionStore }
{ kind: "ephemeral" }
```

## 三种选择

- `new`：创建 durable session。省略 `id` 时 SDK 生成 ID；指定已存在 ID 会返回 `coding_sdk.session_exists`。
- `resume`：只恢复已有 session。不存在时返回 `coding_sdk.session_not_found`，不会静默新建。
- `ephemeral`：在系统临时目录创建 session；成功 `close()` 后删除该目录。

```ts
import { createCodingAgent, type CodingSessionStore } from "@jai/coding-agent";

declare const sessionStore: CodingSessionStore;

const created = await createCodingAgent({
  model: "openai/gpt-4.1-mini",
  cwd: process.cwd(),
  fileCapabilities: {
    homeDirectory: process.env.HOME ?? process.cwd(),
    workspaceDirectory: process.cwd(),
    workspaceTrusted: true,
  },
  session: {
    kind: "new",
    id: "issue-482",
    store: sessionStore,
  },
});
```

SDK 通过 Host-owned store 持久化 Agent 消息和 app state，但不提供“列出所有 session”的 root API。会话 ID 的索引、列表、名称和清理策略属于宿主产品。

## 状态迁移

创建后通常为 `idle`；执行 prompt 时为 `running`；运行错误会投影为 `aborted`；调用 `close()` 后为 `closed`。通过 `agent.state` 读取快照。

`close()` 是宿主资源边界的一部分：它会中止当前工作、等待已接纳的队列和 artifact 写入，然后释放 runtime。无论 prompt 成功或失败，都应在 `finally` 中调用它。进程崩溃或没有调用 `close()` 时，SDK 不保证 ephemeral 临时目录已清理。

参见 [创建 Durable Session](/docs/examples/durable-session)、[恢复 Session](/docs/examples/resume-session) 和 [Ephemeral Agent](/docs/examples/ephemeral-agent)。
