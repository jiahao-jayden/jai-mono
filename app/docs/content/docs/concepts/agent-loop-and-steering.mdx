Agent 的核心是一个确定的有限状态机（Finite State Machine）。SDK 将大模型的多轮交互抽象为原子轮次（Turn）推进循环，同时通过控制面接口提供实时的外部干预能力。

## 状态机流转机制

单次任务调用（`agent.prompt`）的内部状态流转过程如下：

```text
       ┌────────────────────────┐
       │   用户提交 Prompt 输入   │
       └───────────┬────────────┘
                   │
                   ▼
       ┌────────────────────────┐
┌─────►│  1. 上下文组装与断点注入  │◄───────────────────────────┐
│      └───────────┬────────────┘                            │
│                  │                                         │
│                  ▼                                         │
│      ┌────────────────────────┐                            │
│      │  2. 模型流式推理与解析   │                            │
│      └───────────┬────────────┘                            │
│                  │                                         │
│           包含工具调用？                                     │
│            /          \                                    │
│         是/            \否                                 │
│          ▼              ▼                                  │
│ ┌─────────────────┐  ┌──────────────────┐                  │
│ │ 3. 工具参数校验  │  │ 正常终态（完成）  │                  │
│ └────────┬────────┘  └──────────────────┘                  │
│          │                                                 │
│          ▼                                                 │
│ ┌─────────────────┐                                        │
│ │ 4. 权限求值与审批 │                                        │
│ └────────┬────────┘                                        │
│          │                                                 │
│          ▼                                                 │
│ ┌─────────────────┐                                        │
│ │ 5. 批量执行工具  │                                        │
│ └────────┬────────┘                                        │
│          │                                                 │
│          ▼                                                 │
│ ┌─────────────────┐                                        │
│ │ 6. 结果追加与落盘 │───────────────────────────────────────┘
│ └─────────────────┘  进入下一轮次（Next Turn）
```

### 原子轮次（Turn）的六个阶段

1. **上下文前置变换（Before Model Call）**：触发所有已装配扩展的 `beforeModelCall` 钩子，计算 KV Cache 缓存断点，按需压缩历史消息。
2. **流式消费与事件派发**：流式读取模型输出的 Token，向外派发 `text_delta` 与 `thinking_delta` 事件，并在内存中逐步构建实时的 `AssistantMessage`。
3. **参数校验与防御**：模型发出工具调用指令后，SDK 依据工具定义的 Schema 进行强类型校验。
4. **权限判定与审批**：静态分析工具指令是否有潜在越权或破坏性，根据当前 `permissionMode` 决定放行或唤起宿主审批。
5. **批次执行（Batch Execution）**：模型可能在一个轮次中并发发起多个工具调用。SDK 区分串行操作与只读并行操作，捕获执行结果与异常，封装为 `ToolResultMessage`。
6. **落盘与推进**：将完整的消息对追加进会话日志，评估终止条件以决定是否继续推进循环。

## 终止条件判定

Agent Loop 不会无限运行，必须在严格满足下列三者之一时结束：

- **正常终态**：大语言模型在当前轮次输出最终文本，且未发起任何后续 `tool_calls`。
- **协作式中断（AbortSignal）**：宿主显式调用 `agent.abort()`，或调用生命周期结束时发出的超时信号，主循环在当前轮次安全中断。
- **硬性保护预算（maxTurns）**：宿主配置的 `maxTurns` 轮次计数耗尽，强制收尾并返回带有迭代超限标记的结果。

## 防御模型输出协议违规

在极端场景或较弱模型下，模型可能未通过标准的 Function Calling / Tool Call 结构返回工具参数，而是在普通文本中夹带伪造的 XML 或 JSON 字符串（例如 `<tool_call>{"name": "Bash", ...}</tool_call>`）。

SDK 内置了协议拦截层：
- 识别并阻断未经过正常 API 通道声明的伪造工具执行。
- 剥离注入文本，防止模型通过伪造系统前缀篡改上下文。
- 对协议违规行为返回标准化的受控错误或自纠正提示，杜绝非法注入直接穿透至系统 Shell。

## 控制面转向原理（Steering）

在长时间执行复杂任务时，传统的 Agent 往往“一放就跑、无法干预”，直到整场任务失败。SDK 设计了分级控制调度栈：

### 1. 运行中紧急纠偏（`agent.steer`）
当用户调用 `agent.steer(instruction)` 时：
- SDK 不会暴力杀掉进程，而是打断当前轮次之后未开始的工具调度。
- 将用户的纠偏指令作为最高优先级的指导注入当前活跃上下文，并驱动模型在下一个轮次立刻重新思考，实现毫秒级“换方向”。

### 2. 任务排队追加（`agent.followUp`）
当用户调用 `agent.followUp(instruction)` 时：
- 指令进入就绪队列，不影响当前正在进行的推理与工具操作。
- 当当前任务达到正常终态后，SDK 自动无缝出队此指令发起新一轮循环，用户无需手动等待 Agent 空闲再点发送。
