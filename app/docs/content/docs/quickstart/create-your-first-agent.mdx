下面的示例展示了如何创建一个执行当前目录分析的 Agent 实例，并实时监听流式输出与工具调用过程。

```ts
import { createCodingAgent } from "@jai/coding-agent";

// 1. 创建 Agent 实例
const created = await createCodingAgent({
  model: "anthropic/claude-3-7-sonnet",
  cwd: process.cwd(),
  // 缺省时 session 为 { kind: "ephemeral" }，即临时会话，销毁后不留持久化文件
});

if (created.isErr()) {
  console.error("Agent 初始化失败:", created.error.code, created.error.message);
  process.exit(1);
}
const agent = created.value;

// 2. 订阅运行事件（文本流、工具执行状态）
const unsubscribe = agent.subscribe((event) => {
  // 模型流式输出增量文本
  if (event.type === "message_update" && event.assistantEvent.type === "text_delta") {
    process.stdout.write(event.assistantEvent.delta);
  }
  // 工具调用开始
  if (event.type === "tool_execution_start") {
    console.log(`\n[执行工具] ${event.toolName}: ${event.title}`);
  }
});

// 3. 提交任务提示词
const result = await agent.prompt("分析当前目录下的 package.json，总结项目名称与主要依赖");

if (result.isOk()) {
  console.log("\n--- 任务完成 ---");
} else {
  console.error("\n--- 任务失败 ---", result.error.message);
}

// 4. 清理订阅并释放资源
unsubscribe();
await agent.close();
```

## 核心设计要点

- **无抛错设计与 Result 模式**：SDK 的异步操作普遍采用 `better-result` 的 `Result<T, E>` 类型。通过 `result.isOk()` 或 `result.isErr()` 显式处理结果分支，避免在常规业务流中滥用 `try/catch`。
- **配置即入参**：`model` 是唯一的必填字段。若工作区环境已有对应的 API Key 环境变量，`provider` 对象可以完全省略。
- **纯粹的流式回调**：调用 `agent.subscribe()` 注册同步监听器，返回值即为注销回调函数。通过监听 `message_update` 事件可以极为轻松地对接控制台流式渲染或前端界面展示。
- **显式生命周期闭环**：任务全部处理完毕后，必须调用 `await agent.close()`。该调用将优雅等待所有未落盘的日志完成写入、逆序销毁已激活的扩展插件，并回收临时沙箱目录。
