title: SDK 概览
description: 了解公开 SDK 与 Desktop、CLI 等宿主产品各自负责的边界。
---

Coding Agent SDK 把执行循环封装为一个宿主可控的 TypeScript API。调用方给出模型、当前目录和产品策略；SDK 负责模型请求、内置工具、会话、事件和 `Result` 投影。

## 一次调用经过什么

1. 调用方用 `createCodingAgent()` 提供模型引用、可选 Provider 配置、`cwd` 和 session。
2. SDK 创建或恢复会话，装配选中的内置工具和 extensions。
3. 宿主调用 `prompt()`；并发 prompt 按进入顺序串行执行。
4. 工具调用先经过权限层，必要时调用 `requestApproval()`。
5. 宿主从 `Result`、`state` 和 `subscribe()` 取得 JSON-safe 运行数据。
6. 宿主调用 `close()` 释放资源；ephemeral session 的临时目录同时删除。

## 宿主与 SDK 的分工

| 宿主提供 | SDK 提供 |
| --- | --- |
| 模型引用、API key、base URL | Agent 执行循环与 provider 创建 |
| `cwd` 与 session 存储目录 | 内置工具、权限求值和 durable session |
| 授权 UI 或策略 | prompt 队列、abort、close |
| 产品级模型目录、插件发现、连接器 | JSON-safe state / event DTO |
| 自定义 extension | extension 的初始化、工具与 hook 生命周期 |

Desktop 维护自己的 Jai config、Models.dev catalog、插件目录和审批 UI；CLI 也维护自己的 session-layout/plugin-directory 适配。它们不通过一个额外的共享“产品层”耦合。

:::note
`requestApproval` 和 extension callbacks 是进程内函数，不是远程协议。跨进程发送 state、event 或审批数据时，仍应按 UI 用途做白名单 DTO 投影；不要传递 stack、cause、Provider 对象或未筛选的 SDK 错误对象。
:::
