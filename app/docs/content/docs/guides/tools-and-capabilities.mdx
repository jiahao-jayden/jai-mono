description: Read、Bash、Edit、Write 四个内置工具的参数、输出与裁剪方式。
---

SDK 层只有 **4 个**内置工具（`CodingToolName = "Read" | "Bash" | "Edit" |
"Write"`，由常量派生，不可扩展）：

> **澄清**：没有 `find` / `grep` 工具。Bash 工具的描述文字里会建议用
> `grep`/`find`（或 `rg`）做搜索，但那是指 shell 命令。真正的
> `find`/`grep` 工具由 `@jai/extension` 的 `jai.fff-search` 扩展提供，
> 需作为扩展装配。

## Read

`"Read a UTF-8 text file with line numbers."`（可并行执行）

```ts
{ path: string; offset?: number /* >= 1 */; limit?: number /* 1..max */ }
```

输出 content 行格式为 `${行号}|${内容}`，超长行追加 `… [line truncated]`。
`details`（仅日志/UI，不进 LLM 上下文）：
`{ path, startLine, endLine, totalLines, truncated, nextOffset?, truncation? }`。

## Bash

`"Execute a POSIX shell command in the workspace with timeout, cancellation,
and bounded output."`（串行执行）

```ts
{ command: string /* minLength 1 */; timeoutMs?: number /* 1..600_000，缺省 120_000 */; runInBackground?: boolean }
```

- 非零退出码会抛错（tag `tool.bash.non_zero_exit`），不返回结果。
- `runInBackground: true` 用于 `npm run dev` 这类长 running 命令：调用立即
  返回，后台继续跑。成功时 `details` 额外带 `status: "background_running"`、
  `agentId`、`title`（这三个字段实际返回但未在 `BashToolDetails` 接口声明）。
  详见 [后台 Agent](/docs/guides/background-agents)。

## Edit

`"Edit one UTF-8 text file using exact, unique, non-overlapping replacements."`
（串行执行）

```ts
{ path: string; edits: Array<{ oldText: string; newText: string }> /* minItems 1 */ }
```

精确、唯一、不重叠的文本替换；匹配失败时先重读文件再试。文件上限 10MB。
`fileChanges: [{ operation: "modify", path }]`。

## Write

`"Create or completely overwrite a UTF-8 text file."`（串行执行）

```ts
{ path: string; content: string }
```

父目录自动创建。`fileChanges: [{ operation: "add" | "modify", path }]`。

## 工具输出结构

所有工具统一返回 `AgentToolResult`：

```ts
export interface AgentToolResult<TDetails = unknown> {
  /** 回给模型的内容（包进 ToolResultMessage 送回 LLM） */
  content: (TextContent | ImageContent)[];
  /** 完成的文件副作用——可进入 tool-result fact 的受限白名单 */
  fileChanges?: readonly ToolFileChange[];
  /** 给日志/UI 的结构化数据，不进 LLM 上下文 */
  details?: TDetails;
  /** 提示 agent 在本批工具执行完后停止（整批都为 true 才早停） */
  terminate?: boolean;
}
```

三者的去向不同：`content` 给模型看，`fileChanges` 是唯一能进入
tool-result fact 的文件副作用声明，`details` 只给 Host 的日志/UI。

## 裁剪内置工具

```ts
await createCodingAgent({
  model: "anthropic/claude-sonnet-4-5",
  tools: ["Read", "Bash"],        // 白名单：只启用这两个
  excludeTools: ["Bash"],          // 黑名单：在白名单之后再移除；重叠时排除优先
});
```

- 省略 `tools` 则启用全部 4 个。
- 两者都必须是已知内置工具名，否则抛 `coding_sdk.invalid_tool_selection`。
- 扩展提供的工具不受影响（扩展工具是扩展自己的）。

权限侧：工具调用会映射到 `PermissionAction`（Read→`file.read`、
Write/Edit→`file.write`、Bash→`process.exec`、扩展工具→`tool.invoke`），
再走 [权限评估](/docs/guides/permissions)。
