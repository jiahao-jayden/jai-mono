SDK 的内置工具名由 `CodingToolName` 定义：

`Read`、`Bash`、`Edit`、`Write`，以及按需加入的 `UpdateTodos`、`SpawnAgent`。

默认启用四个核心工具。`tools` 用于建立白名单，`excludeTools` 在最后移除工具；两个列表重叠时排除优先。文件搜索由 Runtime Host 装配的 `fffind`、`ffgrep` Extension 提供，不是内置工具名。

```ts
const created = await createCodingAgent({
  model: "openai/gpt-4.1-mini",
  cwd: process.cwd(),
  tools: ["Read", "Edit", "Write", "Bash"],
  excludeTools: ["Bash"],
});
```

这会只保留 `Read`、`Edit` 和 `Write`。非法工具名会让创建返回 `coding_sdk.invalid_tool_selection`。工具选择只影响 SDK 内置工具，不会删除 Extension 自己提供的工具。

## Extension 能力

通过 `defineExtension()` 在顶层声明 tools、skills、hooks、configuration、session state 与 tool catalogs。工具名不能与内置工具或其他 extension 重名。`lifecycle.activate()` 只能创建每个 session 私有的 instance；工具和 hooks 从 `runtime` 取得它，`deactivate()` 负责逆序释放。

```ts
import { Type } from "@sinclair/typebox";
import { createCodingAgent, defineExtension } from "@jai/coding-agent";

const branchExtension = defineExtension({
  id: "current-branch",
  tools: [
    {
      name: "CurrentBranch",
      description: "Return the branch selected by the host.",
      parameters: Type.Object({}),
      authorization: {
        owner: "core",
        permission: { sideEffect: "read", reason: "Reads host-provided branch metadata." },
      },
      execute: async () => ({
        content: [{ type: "text", text: "main" }],
      }),
    },
  ],
});

const created = await createCodingAgent({
  model: "openai/gpt-4.1-mini",
  extensions: [branchExtension],
});
```

每个 Extension 在 activation 时获得 `{ sessionId, cwd, permissionMode, configuration, sessionState }`。`beforeAgentStart` 可以阻止公开 prompt；`beforeModelCall` 只能追加本次请求的受限 synthetic context；`beforeToolCall` 可以继续、改写参数或 block。`turnStart`、`turnEnd`、`afterModelCall`、`afterToolCall` 与 `agentSettled` 都是 observer，失败仅报告 diagnostic。

MCP 等连接后才能枚举的工具使用 `catalogs`。模型初始只看到 core 的 `SearchTools`；搜索到的至多 8 个真实工具从下一次模型请求开始可用。一次新搜索会替换已激活集合，因此不会把完整 catalog 长期堆进 context。

`sessionState` 是 session-local、schema 校验并可恢复的 extension namespace；公开的 `agent.state.appState` 不包含它。完整生命周期与动态工具约束见 [Extension 架构提案](/docs/concepts/extensions-architecture)。

普通 Extension tool 使用 `authorization.owner: "core"`，所以仍由 SDK 的 permission mode、
rules 与 approval handler 管理。只有已实现完整授权事务的 Extension 才能声明
`authorization: { owner: "extension" }`；这会让 core 不再对同一次 tool call 额外审批。

Extension capability 不公开 `mcpServers`。Jai Agent Plugin 的发现与 MCP descriptor 适配属于 `@jai/extension` 和 Desktop/CLI 宿主；最终传给 SDK 的是静态 capabilities 与 catalog descriptor。
