---
title: 权限
description: 配置 permission mode，实现可取消、可关联工具调用的授权回调，并理解不可绕过的安全限制。
---

用户声明的持久化规则写在配置的 `permission` tree，按受保护的 action 分组。用户选择项目级记忆授权时，规则写入用户配置的 `permissionGrants`，并以 canonical workspace 路径分组，不写入项目仓库。`permissions` 只保留 mode、额外目录和 bypass 限制，不再使用 `allow` / `ask` / `deny` 字符串列表。

```json
{
  "permission": {
    "process.exec": { "npm test *": "allow", "git push *": "ask" },
    "file.read": { "**/.env": "deny" },
    "file.write": { "src/**": "allow" }
  },
  "permissions": {
    "defaultMode": "default",
    "additionalDirectories": ["../shared"]
  }
}
```

`permissionGrants` 由宿主在成功保存后生成，不能覆盖当前 `permission` 中的显式 `deny`：

```json
{
  "permissionGrants": {
    "/workspace/project": {
      "process.exec": { "npm test *": "allow" }
    }
  }
}
```

通过顶层 `permissionMode` 选择默认策略，并通过 `requestApproval` 处理需要用户决定的调用：

- `default`：安全读取自动允许，其余按规则或询问处理。
- `acceptEdits`：允许当前目录范围内的常规 Edit/Write。
- `plan`：只允许只读操作；显式 allow 也不会放行写操作。
- `dontAsk`：未预授权的调用直接拒绝，不弹出询问。
- `bypassPermissions`：跳过普通询问，但不能绕过安全层的硬拒绝。

```ts
const created = await createCodingAgent({
  model: "openai/gpt-4.1-mini",
  cwd: process.cwd(),
  permissionMode: "default",
  requestApproval: async (request, signal) => {
    if (signal?.aborted) return "deny";
    console.log(request.summary.title, request.summary.description);
    return request.summary.risk === "low" ? "allowOnce" : "deny";
  },
});
```

审批请求包含 `requestId`、`sessionId` 和 `toolCallId`，用于宿主内部关联 pending UI 与工具行。展示时优先使用 `summary`，不要把原始 `args` 当作安全、可直接渲染的数据。

## 安全层

- 递归删除 root/home 等高风险目标始终拒绝，即使使用 `bypassPermissions`。
- 删除和带文件重定向等 destructive Bash 至少需要更严格的决策。
- danger request 的 `canAlwaysAllow` 为 false；`alwaysAllow` 不会绕过该限制。
- `plan` 固定拒绝 `Write`、`Edit` 和可写 Bash。

审批 handler 是进程内回调。桌面端需要通过 IPC 时，应把 `CodingPermissionRequest` 投影为白名单 UI DTO，并将用户决定映射回三个公开 decision 值。完整代码见 [Approval Flow](/docs/examples/approval-flow)。
