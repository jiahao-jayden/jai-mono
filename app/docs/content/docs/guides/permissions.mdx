---
title: 权限
description: 配置五种 permission mode，实现可取消且可关联工具调用的宿主授权回调，并理解 danger layer 中不可绕过的安全硬拒绝。
---

通过 `execution.permissionMode` 选择默认策略，通过 `host.approval.request` 处理需要用户决定的调用。

- `default`：安全读取自动允许，其余按规则或询问处理。
- `acceptEdits`：自动允许 workspace 边界内的 Edit/Write。
- `plan`：只允许只读操作；显式 allow 也不能放行写操作。
- `dontAsk`：未预授权调用直接拒绝，不弹出询问。
- `bypassPermissions`：跳过普通询问，但不能绕过 danger layer 的硬拒绝。

可运行的 Node.js CLI 实现见 [Approval Flow](/docs/examples/approval-flow)。它直接构造完整 Host，不依赖预设对象，并处理取消、输入失败和 readline 关闭。

权限请求含稳定关联字段 `requestId`、`sessionId`、`toolCallId`，并包含工具名、JSON-safe args、reason、安全摘要与建议规则。UI 应优先渲染 `summary`；不要把原始 args 当作无条件安全的展示内容。

## 安全层

- root/home 的递归强制删除始终拒绝，即使使用 `bypassPermissions`。
- 删除、文件重定向等 destructive Bash 至少询问，不能被普通 allow 配置静默放行。
- danger request 的 `canAlwaysAllow` 为 false；伪造 `alwaysAllow` 会被拒绝。
- workspace 外文件访问默认询问；`defaultAllowedDirectories` 控制基础边界。

`plan` 已实现：Read、Glob、Grep 及只读 Bash 可运行；Write、Edit 和可写 Bash 固定拒绝。

完整流程见 [Approval Flow](/docs/examples/approval-flow)。
