---
title: 错误处理
description: 在创建、运行、控制与关闭时正确处理 CodingSdkError 和 Result。
---

公开 SDK 把调用方可恢复的失败表示为 `Result<T, CodingSdkError>`。先分支 `isErr()`，再读取 `value`：

```ts
import { createCodingAgent } from "@jai/coding-agent";

const created = await createCodingAgent({ model: "openai/gpt-4.1-mini" });
if (created.isErr()) {
  console.error(`${created.error.phase}: ${created.error.code}`);
  console.error(created.error.message);
} else {
  const closed = await created.value.close();
  if (closed.isErr()) console.error(closed.error);
}
```

`CodingSdkError` 固定包含：

```ts
type CodingSdkError = {
  code: string;
  message: string;
  retryable: boolean;
  phase: "runtime_creation" | "session" | "admission" | "model" | "tool" | "permission" | "compaction" | "lifecycle";
};
```

适合用户提示或重试判断的字段只有这些公开 DTO 字段。不要假定错误包含 `requestId`、`toolCallId`、`details`、stack、cause 或底层 provider 错误；审批请求和事件有自己的关联字段与投影契约。

`coding_sdk.missing_credentials`、`coding_sdk.invalid_model_ref`、`coding_sdk.unsupported_provider` 与 `coding_sdk.invalid_provider_configuration` 适合引导配置修复；session、permission 和 lifecycle 错误则应结合当前用户操作显示。只有程序 invariant 或未知基础设施故障才可能以原生异常出现。
