## CLI

```bash
jai
```

无 prompt 且 stdin 是 TTY 时，CLI 进入交互模式。使用 `-p` 可以在 CI、脚本或 benchmark 中运行一次非交互 prompt。

```bash
jai -p "修复失败的测试" \
  --output-format stream-json \
  --permission-mode bypassPermissions
```

## 常用参数

| 参数 | 说明 |
| --- | --- |
| `-p, --print [text]` | 运行一次非交互 prompt。stdin 也可提供 prompt。 |
| `--output-format <text\|json\|stream-json>` | 控制人类、单次 JSON 或逐事件 JSON 输出。 |
| `--model <profile/model>` | 覆盖当前配置的模型。 |
| `--cwd <path>` | Workspace root，默认当前目录。 |
| `--session-id <id>` | 只恢复一个已存在的 durable Session。 |
| `--no-session-persistence` | 使用进程结束后清理的 ephemeral Session。 |
| `--permission-mode <mode>` | `default`、`acceptEdits`、`dontAsk` 或 `bypassPermissions`。 |
| `--max-turns <n>` | 限制一次 prompt 的最大 model turn。 |

`plan` 目前会以 typed unsupported outcome 失败，不能通过 prompt 模拟。

CLI 会加载用户目录下的 `.jai/plugins`、`.agents/plugins`，并只在 `--trust-workspace` 时加载当前 workspace 的同名插件目录。插件包的发现和验证由 `@jai/coding-agent` 完成；CLI 不自行装配工具。

## 自动化

`stream-json` 是自动化入口。CLI 将 SDK canonical Agent events 投影为稳定的 `system`、`assistant`、tool lifecycle 和 `result` 记录，并在结尾写入 token usage 与总成本。权限无法在无 TTY 环境解决时，命令会失败而不是挂起或隐式允许。
