一次命令，
三层判断。

OpenCode 不会把 Bash 当成一条黑盒字符串。它先把命令解析成树，再从树里提取命令节点，最后把每个节点交给规则与路径边界分别裁决。

tree-sitter-bash findLast patterns / always external_directory

Jai 不直接把整行字符串交给权限规则，而是按“解析、提取、裁决”三步处理。分类（只读、普通、危险）发生在最后一步里。

03

裁决

先识别只读或危险操作，再匹配规则；所有子命令通过后，整条调用才会执行。

A small vocabulary

AST 不是“更漂亮的字符串”。
它是一种结构。

Abstract Syntax Tree，抽象语法树。它把源文本里有意义的语法关系保存下来：谁是命令、谁是参数、谁连接了两个命令、谁包住了谁。

node

节点

树上的一个语法单位。command、word、pipeline 都是节点类型，而不是权限动作本身。

parent / child

父子关系

command 节点可以拥有 command_name 与参数子节点。父节点说明组合关系，子节点保存具体片段。

span

原文范围

每个节点都能指回原始字符串的一段范围。OpenCode 用 command 节点的原文生成当前调用的 pattern。

字符串视角

“这是一条命令。”信息足够少，无法区分 git status 与 rm -rf 是否同时存在。

git status && cat ../notes.md | head -20

树视角

“这里有两个 command 节点，它们被 operator 连接；每个节点都可以单独进入权限判断。”

program → command → command_name + word…

The permission pipeline

一条 Bash 调用经过五个转折点。

这里最重要的分离是：AST 负责理解“命令里有什么”，规则负责决定“是否允许”，路径 authority 负责决定“它能碰到哪里”。三者不是同一层。

01

原始输入

工具收到未经信任的 Bash 字符串。

02

解析 AST

tree-sitter 识别 command、pipeline、operator。

03

提取节点

遍历所有 command 节点，生成多个请求候选。

04

规则匹配

permission 与 pattern 同时匹配，最后一条胜出。

05

执行或询问

全部为 allow 才放行；deny 立即失败，ask 才建立待处理请求。

The rule engine

规则不是“越具体越优先”。
是最后匹配的那条赢。

OpenCode 会把规则扁平化，然后从后往前找同时匹配权限名与 pattern 的规则。没有匹配时默认 ask。这就是 findLast 的实际含义。

为什么要保留顺序？

用户可以先写一个宽泛默认值，再在后面用更窄的 pattern 改写。顺序就是配置作者表达“例外”的方式。

"*" → ask
"git status" → allow

一个常见误解

“deny 一定比 allow 优先”不是 OpenCode 这条实现的算法。优先级来自列表位置，而不是 action 名字的重量。

findLast(match(rule)) → action

Two different memories

patterns 和 always，不是一回事。

一次权限请求会同时携带“这次到底执行了什么”和“如果用户选择 always，未来应该记住哪一个稳定命令族”。前者忠实，后者故意抽象。

patterns · 当前事实

取 command AST 节点的原文，描述当前这一次调用。它可以包含完整参数。

patterns: ["git status"]

always · 稳定前缀

通过 BashArity 词典确定命令前缀，再补上 *。不是把一条偶然参数永久放行。

always: ["git status *"]
arity dictionary 的直觉longest prefix wins
git默认：git *
git remote更长：git remote *
npm run稳定：npm run *

A separate boundary

命令能不能执行，和它能碰到哪里，分开问。

OpenCode 对 Bash 命令做一套权限判断，同时对可解析的文件路径做另一套 external_directory 请求。命令 allow 不等于文件系统 sandbox。

Bash policy

判断命令模式是否匹配 allow / ask / deny。

bash: cat ../notes.md
+

Path authority

判断路径是否越过 workspace。可解析的父目录会单独发起询问。

external_directory: ../notes.md
importantallow("cat *") ≠ allow(read outside workspace)
!

OpenCode 的 AST 很强，但它不是安全证明。

AST 告诉系统“这里出现了哪些语法节点”，不告诉系统脚本内部一定不会删除文件。固定源码快照中也没有看到把 rm、危险重定向、git clean 强制锁成 ask/deny 的不可覆盖风险层。

Keep these words apart

读完以后，至少不要再混淆这六个词。

AST
语法结构树，保存节点与父子关系。
command node
AST 中代表一次命令调用的节点，OpenCode 会遍历它。
pattern
描述本次调用的原文模式。
always
用户批准未来命令族时要持久化的稳定前缀。
findLast
从规则列表尾部寻找最后一个匹配项。
external_directory
工作区外路径的独立权限请求，不是 Bash 规则本身。
