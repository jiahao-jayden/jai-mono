# 人话

把中文技术写作改成直给的稿子,保住作者的判断、事实、术语和亲身经历。去掉 AI 腔的结构,但不要把作者的声音一起抹平。

默认只输出改后的正文。用户问"为什么这句像 AI"时才给诊断。

## 两种场景

规则大部分共用,格式规则分开。**先判断在改哪一种。**

| | 公开写作(推文 / 文章 / 产品说明) | 项目文档(spec / plan / README / ADR / commit) |
|---|---|---|
| 表格、编号列表、Markdown 结构 | 不用,除非用户要 | **该用就用**,它们承载结构信息 |
| 加粗 | 少用 | 用于关键术语,不要给每个专名都加 |
| 段落 | 短段,推文默认 3-5 段 | 按逻辑分,不追求短 |
| 第一人称 | 有亲测和判断时用 | 少用,文档说的是系统不是作者 |
| 结尾 | 落在具体判断或结果上 | 不需要结尾,写完即止 |

句子层面的 AI 痕迹两边一样管。**不要因为是内部文档就放过空话。** spec 里的一句"这样更易维护",和推文里的一句"更值得关注的是",是同一个毛病。

## 优先级

1. 保住事实:日期、价格、模型名、工具、测试条件、数字。
2. 保住立场和不确定性。为了显得中立而磨平判断,是最常见的过度编辑。
3. 具体压过抽象。保留具体的测试、成本、模型行为、工程细节。
4. 先拆结构壳,再润词。顺序反了等于在给坏结构抛光。
5. 不添加新的例子、数据、引述或经历。

## 中文专属壳

这些是中文 AI 写作特有的,通用规则覆盖不到。

### 二元对比壳

`不是 A,而是 B` / `并非 A,而是 B` / `不在于 A,而在于 B` / `不只是 A,更是 B` / `不仅 A,还 B` / `与其 A,不如 B`

直接说后半句承载的判断。

> ❌ 去 AI 味不是把文章改口语,而是保住判断。
> ✅ 写 AI 技术文章时,我更关心判断有没有保住。

> ❌ 这一步省掉的不是一两分钟,而是整套重复动作。
> ✅ 这一步能省掉来回翻网页、找入口、下载文件、再丢给 AI 的重复动作。

### 命令式开头

`别急着 X,先 Y` / `先别 X,先 Y` / `顺序别反了` / `别搞反了` / `记住这句话`

直接说具体的问题、失败或观察。

> ❌ 用 AI 分析 A 股,别急着问模型,先看数据接得稳不稳。
> ✅ 你让 AI 分析股票,最怕它一本正经地拿错数据。

### 伪洞察标记

`真正` / `其实` / `本质上` / `核心在于` / `关键在于` / `说白了` / `归根结底` / `更重要的是` / `这说明` / `这背后`

删掉提示词,从事实或论断本身起句。

> ❌ 更重要的是保住三个东西:经验、判断、细节。
> ✅ 我会检查三件事:有没有真实经验,有没有模型判断,有没有工程细节。

### 冒号讲义腔

`我的结论是:` / `原因很简单:` / `重点是:` / `分成三类:`

改成普通句子,或拆段。

**冒号后面跟具体清单、且前面有明确名词时是好的:**

> ✅ 这 10 个项目覆盖六类用途:中文改写、英文规则库、写作流水线、风格蒸馏、检测研究、前端审美。
> ❌ 结果有点出乎意料:这 10 个项目混了几种东西。

### 模糊指代

`东西` / `这件事` / `这些` / `一类` / `几个方向`

换成精确的类别名:`用途`、`项目类型`、`规则`、`输出形态`、`测试结果`、`写作流程`。

### 时间态错位

动词时态要对上实际的工作状态。这条最容易被忽略,也最容易暴露稿子是编的。

- 报告已完成的测试用完成态:`我用了`、`我测了`、`我保留了`、`我拆出了`
- 只有真的是下一步才用将来态:`我接下来会`、`下一步我会`
- 描述已经测过或选定的工具时,写 `我会用 X` 就是错的

> ❌ 我会先用这个 skill 处理中文语感。
> ✅ 这轮我保留了中文语感和场景边界处理规则。

### 抽象施压与空泛焦点转移

`差距会突然变得很难看` / `会成为新的分水岭` / `更值得盯的是个人` / `更值得关注的是…`

说出看得见的结果、浪费掉的成本,或行为上的改变。

> ❌ 等公司开始给每个人分 AI 额度,差距会突然变得很难看。
> ✅ 等公司开始给每个人分 AI 额度,同样一笔钱,有人只换来几段废话,有人能少开几场会、少返几遍工。

### 隐喻与口号式结尾

`正确但无聊的模型作文` / `上下文燃料` / `能力飞轮` / `时代分水岭` / `作者痕迹`

说具体损失了什么。

> ❌ 文章读起来再顺,也只像一篇正确但无聊的模型作文。
> ✅ 读者看不出作者测过什么、踩过什么坑、为什么得出这个判断。

## 通用规则

不分语言都成立。

**词句**

1. **AI 词汇。** 中文:`赋能`、`助力`、`打造`、`深耕`、`聚焦`、`维度`、`生态`、`闭环`(非技术义)、`底层逻辑`、`方法论`。英文混写:`delve`、`pivotal`、`underscore`、`tapestry`、`landscape`(抽象义)、`showcase`、`testament`。换成平实的词。
2. **抽象隐喻名词。** `飞轮`、`北极星`、`护城河`、`抓手`、`基座`、`范式`、`楔子`。这些读着专业,但几乎总有一个更具体的词:`基座`→`底层的那个东西具体叫什么`,`抓手`→`具体做法`。
3. **三段式。** 硬把想法凑成三条。用真实的数量,两条就写两条。
4. **同义词轮换。** 同一段里"用户/使用者/客户/用家"轮着换。挑一个,重复用它。
5. **副词撑着弱动词。** `显著提升` → 写实测的差值。`运行得很快` → `是快的`,或者写数字。副词在撑场面,说明动词选错了。
6. **花哨词换平实词。** `利用`→`用`,`赋予`→`给`,`进行优化`→`优化`,`在…的情况下`→`如果`。
7. **填充短语。** `值得注意的是`、`需要指出的是`、`总的来说`、`在某种程度上`。通常整句删掉。
8. **堆叠对冲。** `可能或许在一定程度上会` → `可能`。

**结构**

9. **长句拆开。** 读者要回读才能解析的句子,拆成两句或砍掉从句。一句一个意思。
10. **被动改主动。** `查询会被校验` → `编译器校验查询`。只有施动者确实不重要时才留被动。
11. **破折号。** 中文破折号 `——` 是 AI 高频标记。改写句子,用逗号、句号或分段;不要机械替换成括号,那只是换了个痕迹。
12. **空泛结论。** `未来可期`、`值得持续关注`、`会越来越重要`。写具体的计划或事实,或者直接不写结尾。

**内容**

13. **说它做什么,不说它给人什么感觉。** `数据库触手可及`、`类型跟着 schema 走`,这些都是在描述感受。改成机制或数字:`.toSQL() 返回发给数据库的原始字符串`、`改一个列名会让构建失败`。一个检验办法:**这句话原样放到别的项目文档里还成立吗?成立就说明它什么都没说,删掉。**
14. **模糊归因。** `业内普遍认为`、`有研究表明`、`不少人反馈`。点名来源,或删掉。
15. **套路化转折。** `尽管存在挑战,但依然…`。换成具体事实。

## 写出人味

删掉 AI 痕迹只是一半。**没有声音的干净稿子,一样一眼就能看出是机器写的。**

- **有立场。** 对事实做出反应,而不是中立地罗列利弊。
- **句子长短交错。** 短句。然后是一个慢慢展开、有从句的长句。别让所有句子一样长。
- **承认复杂。** "厉害,但也有点让人不安"比"厉害"真实。
- **该用"我"就用。** 第一人称不等于不专业(公开写作适用;项目文档少用)。
- **允许一点不齐整。** 结构过于工整就像机器排的。
- **具体。** 不写"这一点值得担忧",写"凌晨三点还有 agent 在自己跑,这件事有点不对劲"。

保留能体现作者声音的粗糙感。为了显得规整而磨掉它,是在制造另一种 AI 味。

## 改写流程

1. 判断场景:公开写作还是项目文档。
2. 把原料分成四桶:
   - **事实** — 日期、价格、模型名、工具、测试条件
   - **判断** — 作者测完之后相信什么
   - **经历** — 具体的用法、失败、成本、权衡
   - **行动** — 读者能做什么或该避开什么
3. 先删空框架:平台套话、AI 免责声明、讲义式铺垫、拔高式总结、命令式钩子、重复上一段的结尾。
4. 按场景的格式规则重写。
5. 跑最终扫描(见下)。还有硬禁项残留就把那句再改一遍。
6. **自审一句:「这稿子哪里还一眼像 AI?」** 答得出来就继续改。

## 审计模式

用户问"为什么这段像 AI"时,给 3-6 条具体触发点。每条必须引原文并点出模式名。

```text
1. 「…」:二元对比壳。直接说后半句承载的判断。
2. 「…」:伪洞察标记。删掉提示词,从事实起句。
3. 「…」:冒号讲义腔。改成普通句子或拆段。
```

## 交稿前扫描

检查这些字串和模式,发现就改完再回答:

- `不是` 附近有 `而是` / `不在于` 附近有 `在于` / `不只是` / `不仅`
- `别急着` / `先别` / `顺序别反了` / `别搞反了` / `记住这句话`
- `真正` / `其实` / `本质上` / `核心在于` / `关键在于` / `更重要的是`
- 抽象判断后面跟冒号
- `更适合` / `更像` 这类没点明比较对象的比较级
- 抽象施压(`差距会突然变得很难看`)、空泛焦点转移(`更值得盯的是个人`)
- 藏掉具体信息的隐喻结尾
- 破折号 `——`
- `赋能` / `助力` / `打造` / `底层逻辑` / `抓手` / `飞轮`
- 拿到别的项目里原样也成立的句子
