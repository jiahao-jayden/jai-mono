# 实施与 Review

## 一个任务一个执行上下文

调度者读取父 PRD、确认和任务依赖，每次选一个可开始的子任务，创建新的执行上下文，不让上一个任务的完整检索和实施记录进入下一个任务。单次 JN 默认顺序循环；用户可以在不同会话并行工作。

交给执行者：仓库与工作目录、父/子记录链接或路径、适用的已确认范围、项目规则位置、前置交付物与必要交接、任务验收条件，以及本轮是否只读。执行者重新读取任务和相关 PRD，不依赖调度者的摘要替代原文。

完成后只返回结果、检查摘要、代码/产物位置、遗留问题和任务记录位置。完整证据保存在 GitHub 评论或本地任务的「执行记录」。工具不支持独立上下文时提供含上述内容的新会话交接，不在同一长会话里循环并声称已隔离。

用户只要求查看或 Review 时，只读检查并交付发现，不认领实施、不修代码，也不更新或关闭 tracker 记录，除非这些动作另有明确授权。

## 启动前

1. 核对父 PRD 及任务范围已获确认，检查任务仍打开、无其他执行者。
2. 读前置任务的状态和交付物。只有 completed 且当前环境可访问所需代码或产物，依赖才满足。取消、状态不明或只有远端不可访问的代码都不满足。
3. 读项目规则、当前任务全文和相关 PRD。自己查清涉及的数据与维护方、不可改动的范围、现有代码和检查命令；普通实现细节不再询问用户。
4. 将阶段切换为 `jn:in-progress`，记录执行者/会话、工作位置和时间，再重读确认没有另一执行者。执行信息不是原子锁；发现并发认领就停止冲突项并协调，不抢占。
5. 检查工作目录现有改动和可能的并行任务。认领任务不隔离文件；重叠改动先协调，不能自动 stash、reset、切分支或覆盖他人的工作。

过期的执行信息不等于任务已无人负责。通过会话、进程或用户提供的信息核实，无法确认时不直接接管。

## 实施循环

默认选依赖已满足、未被认领的任务；多个任务可开始时按子任务顺序选择，用户明确指定时优先处理指定任务。阻塞项只在阻塞原因消除后重试，避免反复挑选同一失败项。

按任务范围实施，必要时单独调用 `research`，证据返回后继续当前任务。局部决定写入任务执行记录；新目标、范围、外部行为或重大风险变化返回 PRD 更新和确认，只暂停受影响的工作。

从项目实际配置、脚本和已有约定选择检查。代码改动跑相关测试及适用的静态检查；脚本检查语法和行为；文档检查结构、引用和图示。没有测试脚本或类型检查工具时说明事实，给出适用的检查方式，不编命令。

检查失败先定位和修复。无法修复时保持任务打开、记录命令与真实错误，注明环境问题、已有失败或本次回归及判断依据。不得跳过失败直接关闭；可以继续不依赖它、且不会产生文件冲突的任务。

## 单项完成记录

实现完成进入检查时将阶段切换为 `jn:review`。可继续修复的失败回到 `jn:in-progress`，无法推进才标 `jn:blocked`；更新父记录时按 Tracker 操作约定汇总，不把单个子任务阻塞传播成整个需求阻塞。

执行者对照每条验收条件检查实现和遗漏，回写执行记录：

- 完成了什么，对应哪些验收条件。
- 实际运行的命令、环境/工作目录、关键原始输出和结果；人工检查写操作及观察。
- 代码与产物位置。有现成提交时记录完整 SHA，没有提交则写明“未提交”、工作位置及改动文件，不自动 commit 或 push。
- 局部决定、已知限制、未处理事项，以及下游取得产物的方法。

调度者检查证据是否足够，重新读取任务后以 completed 关闭并清除阶段；失败或证据不足就保持打开。关闭成功后继续下一个可执行任务，写入失败先按 Tracker 操作约定恢复。

## 整体 Review

在已有写入授权时，将待整体验收的父记录阶段切换为 `jn:review`。子任务全部完成或按用户决定取消后，用新的只读审查上下文对照父 PRD 和实际代码/产物进行 Review。读代码和运行检查，不只看实施者的完成摘要；上下文隔离不可用时明确说明并提供审查交接。

检查：主流程与异常分支是否兑现，图示与实现是否一致，跨任务数据/接口是否接通，兼容性和项目规则是否满足，原有行为是否回归，以及每条 PRD 验收是否都有证据。无法在同一环境获得完整成果时记录整体验收阻塞，不把各项局部通过当成整体通过。

已有实施和 tracker 写入授权时，范围内缺陷重开对应任务或创建修复任务，保留旧检查记录，修复后重跑相关检查和整体验收。仅获只读 Review 授权时到此交付发现，不进行这些写入或修复。范围外发现只记录，得到范围授权后才安排实施。用户取消过的任务若留下验收缺口，必须先调整 PRD 并记录确认。

已有 tracker 写入授权时，在父记录写入验收清单、真实检查结果、代码/产物位置及剩余限制；仅只读 Review 则在对话交付这些结果，不改记录。允许回写且通过整体验收后以 completed 关闭并清除阶段，更新 RFC 的回顾安排；只有实际完成复盘才勾选“复盘完成”。普通交付汇报不能冒充复盘。
