# 子任务正文模板

以下是草稿结构。首次创建时填真实父记录链接或相对路径，删除填写提示；尚无真实编号的前置任务可暂留草稿标识。所有子任务创建后再替换依赖引用并补齐关系，未完成前不实施受影响的任务。不适用的技术条目说明原因。

```markdown
父需求：<父记录链接或相对路径>
草稿标识：<T1；发布后保留，用于重试定位>

## 交付结果
<完成后什么行为可以使用；对应父 PRD 哪些验收条件。>

## 范围
做：<本项行为和必要改动。>
不做：<其他任务或计划外内容。>

## 背景与约束
<本项需要的整体选择及父 PRD 对应章节；项目规则摘录与出处。>
<会改动的持久数据、维护模块、兼容或失败要求；不涉及则说明。>

## 前置交付物
<前置任务及链接、需要的代码或产物；无则写无。>
<依赖以原生关系为准；使用链接回退时在这里明确说明。>

## 开始前核对
- 读取父 PRD、当前任务、相关项目规则和前置交接。
- 确认范围已获授权、前置成果在当前环境可用。
- 检查是否已有执行者及工作目录中的重叠改动；冲突时不接管或覆盖。

## 验收条件
- [ ] <用户或调用方可观察的结果及重要异常分支。>

## 检查方式
<实际查到的命令、执行目录与用途；人工检查写步骤及预期观察。>
检查未通过或缺少证据时保持任务打开。完成后执行记录写入实际输出、
代码/产物位置、局部决定、限制和交接，才能以 completed 关闭。

## 执行信息
执行者/会话：无
工作位置：未分配
更新时间：<日期时间>
阻塞原因：无
```

类型和阶段由 JN 按 Tracker 操作约定写入 GitHub labels 或本地 frontmatter，不写进正文。执行信息仅用于打开的任务，关闭时清除。实施证据按时间追加到 GitHub 评论或本地「执行记录」，不把整份日志塞进正文。
