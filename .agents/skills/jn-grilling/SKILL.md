批量拷问,直到达成共识。把问题建成一棵**决策树**:每个决策分叉出挂在它下面的决策。

按**轮**推进。**前沿**是所有前提已确定的决策,也就是现在就能问、不必猜测未知答案的问题。**一轮问完整个前沿**,然后停下等回答。绝不一个一个弹问题。

## 先自查,再提问

事实是你的活,决策是用户的活。

提问前先查环境。以下都不许问用户:

- 项目约定、编码规则、架构规则 → 读 `AGENTS.md` / `CLAUDE.md`
- 领域词汇 → 读 `CONTEXT.md`
- 现状、已有实现、文件位置 → 读代码
- 最近改过什么、谁在动 → `git log`
- 已有决策 → 读 `docs/adr/`、项目里已有的规划文档

查到的写成**既定前提**告知用户,不占提问额度:

```
📌 已查明(无需你回答):
- 错误处理走 `better-result` 的 `Result<T, E>`,领域错误用 `TaggedError`(AGENTS.md)
- `SessionStore` 接口已存在,append + expectedRevision 的 CAS 语义(packages/agent/src/harness/session/types.ts:61)
```

需要环境事实但代价较高时,派 subagent 去查。不要阻塞:正在跑的探查是一个未确定的前提,只有它下游的问题等结果,前沿其余问题现在就问。

事实在**仓库之外**(第三方库怎么实现、协议怎么定义、别的项目怎么解决同一问题),**派一个 subagent 去做,让它调用 Skill 工具传 `research`**,回来只要结论和笔记路径。

调研要读大量文档和源码,在当前上下文里跑会把这些原文灌进访谈,挤掉你正在推进的决策树。隔离出去,拿回来的是一份带引证的笔记,那比对话里的一句转述更经得起后面反复引用。笔记存到哪由调用方决定。

只有**真正需要用户拍的决策**才进入提问。

## 提问格式

每题必须带:选项、每个选项的代价、推荐项、推荐理由、连带影响。

```
❓ **Q1** - <问题标题>

<背景:为什么这是个需要决定的问题。可以多段。>

- **A**(推荐):<做法>。代价:<代价>
- **B**:<做法>。代价:<代价>
- **C**:<做法>。代价:<代价>

➡️ 推荐 **A**,因为 <理由>。选 A 会连带 <这个选择往下会影响什么>。

---
```

规则:

- **选项 2-3 个**。只有一条路可走时,不要硬凑选项:直接写成既定前提。
- **代价必须具体**。"更复杂"不算代价;"要多维护一个 adapter,且 contract test 得跑两遍"才算。
- **推荐必须有理由**。没有理由的推荐等于没有推荐,用户无法判断该不该反驳你。
- **连带影响是这套格式的关键**。用户要看到选 A 之后哪些后续问题会消失、哪些会出现。
- 每题之间用 `---` 分隔。
- 答案依赖本轮另一个未决问题的,属于**下一轮**,不是这一轮。

## 推进

每轮回答会重塑树:已定的决策把前沿往外推,解锁依赖它们的问题。重算前沿,问下一轮。

用户回一个序号(`1A 2B`)就该能推进。用户给的是自然语言而非序号,照常接受。

用户反驳你的推荐时,不要顺着改。先说清你原本的理由在他的反驳下哪一条不成立了,再更新。理由被推翻才改,单纯被反对不改。

## 完成

前沿为空即结束:决策树每个分支都走过,没有任何东西被默默假设。

结束时输出一份**决策清单**:每条一行,`决策 → 选择 → 一句理由`。这份清单是下游工件的输入。

未经用户确认已达成共识,不得据此行动。
