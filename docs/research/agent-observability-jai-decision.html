先做哪四个 POC

候选 代表方向 第一验证点 不能默认假设
OTel + Collector + backend协议、采样、脱敏与后端解耦OTLP、async context、tail sample、迁移自带 eval/反馈/回放 UI
Langfuse自托管 trace、score、prompt、cost、alertDocker、数据边界、score 与 async traceSDK 就是通用 OTLP ingest
MLflow Tracing自托管实验系统与 OTel 双写OTLP ingest/export、生产权限与 eval本地 demo 等同生产部署
Opik自托管 Agent trace 与 online evaluationK8s/存储、judge 成本、alert、退出Apache-2.0 消除运维和治理成本

四者不预设胜者。对每个候选跑相同 12 项 fixture：多步骤、工具重试、权限拒绝、provider 故障、异步、会话、成本、脱敏、反馈、evaluator、告警与退出。详见综合笔记与平台证据矩阵。

对 JAI 的直接影响

第一步不是购买平台，而是固定安全的 TelemetryEvent 投影，并把 exporter 放到 host/adapter。复用 Journal、runtime event、trajectory 与 TaggedError 的已有边界；优先记录审批与真实 tool effect，再逐步完成 OTel 和四个候选的 POC。

尚待产品决策

数据是否可离开设备/私有网络、内容的保留与删除规则、是否需要人工复核或线上 judge、现有 APM/MLflow 基础设施、许可证审查与运维 owner。这些决定部署和内容 policy，不能由 SDK 选择替代。
